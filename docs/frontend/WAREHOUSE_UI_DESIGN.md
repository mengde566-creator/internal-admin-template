# 0.2 仓储界面设计与文案契约

> 状态：已确认
> 版本：0.2
> 适用范围：仓储人工业务页面及后续仓储 Agent 侧栏
> 更新日期：2026-08-16

## 1. 设计目标

仓储界面面向日常办公人员，按“查询库存、办理库存业务、维护物品与库位、追溯库存记录”的任务组织，不按数据库表、后端模块或技术对象组织。

本次设计保持现有 Vue 3、Element Plus、Vue Router、全局布局和主题令牌体系。禁止为了视觉改造更换前端架构、引入第二套主题变量或增加无真实调用者的通用页面框架。

## 2. 页面结构

仓储模块包含以下五个用户入口：

| 入口 | 核心任务 | 主要使用者 |
| --- | --- | --- |
| 库存查询 | 按物品、仓库和库位查询当前库存 | 仓储查询用户 |
| 库存操作 | 办理入库、出库、调拨和盘点 | 仓储操作用户 |
| 物品 | 新增、编辑、启停物品并查看库存 | 仓储维护用户 |
| 仓库与库位 | 维护仓库所属部门及仓内库位 | 仓储维护用户 |
| 库存记录 | 查询和查看入库、出库、调拨、盘点记录 | 仓储查询用户 |

入口按权限显示。仓储模块内部可以使用子路由承载上述页面，但不得把它们拆成新的前端应用或全局业务模块。

## 3. 页面契约

### 3.1 库存查询

- 作为仓储默认入口；
- 提供物品编码或名称搜索、仓库和库位筛选；
- 表格至少展示物品、仓库、库位、现有数量、单位和操作；
- 查看状态不得直接出现可编辑输入框；
- 支持从结果进入物品或库存详情；
- 首次无物品、筛选无结果、加载失败必须使用不同状态和动作。

### 3.2 库存操作

页面先明确选择入库、出库、调拨或盘点，随后只展示当前业务需要的字段。禁止继续使用一张通用表单配四个提交按钮。

#### 入库

- 选择目标仓库和目标库位；
- 明细展示物品、入库数量、单位和行备注；
- 支持整单备注和有限多明细；
- 主操作文案为“确认入库”。

#### 出库

- 选择来源仓库和来源库位；
- 明细展示物品、当前库存、出库数量、单位和行备注；
- 库存充足与库存不足必须直接表达；
- 主操作文案为“确认出库”。

#### 调拨

- 同时展示来源仓库、来源库位、目标仓库和目标库位；
- 明细展示当前库存和调拨数量；
- 提交前明确检查来源与目标不同、库存充足和必填项完整；
- 主操作文案为“确认调拨”。

#### 盘点

- 选择盘点仓库和盘点库位；
- 明细展示账面数量、实际数量和自动计算的差异；
- 盘点说明必填；
- “关联原记录”只在纠正历史操作时使用，不暴露内部字段名；
- 主操作文案为“确认盘点”。

所有库存操作均提交后直接生效，不展示草稿、审批或复核入口。提交成功后展示业务编号和“查看库存记录”动作。

#### 库存操作布局与位置语义

- 一张入库单、出库单或盘点单只选择一个整单库位；顶部选择的仓库和库位适用于本单全部明细，明细行不得再次展示或要求选择库位；
- 一张调拨单只选择一组整单来源和目标；顶部选择的来源仓库、来源库位、目标仓库和目标库位适用于本单全部明细，明细行不得重复展示来源或目标库位；
- 多明细用于同一业务位置下同时办理多个物品，不表示每一行可以选择不同仓库或库位；切换整单仓库或库位后，前端必须重新校验全部明细的库存提示和提交参数；
- 整单位置区使用稳定栅格：入库、出库、盘点在桌面为两个等宽字段，调拨为四个等宽字段；中等宽度下调拨改为两列两行，窄屏统一单列；
- 所有字段标签位于控件上方，标签、必填标记、控件和帮助文字使用统一垂直节奏；禁止把裸 `el-form-item` 放入不确定列数的网格后依赖自动换行；
- 明细行必须使用显式列定义和独立删除操作列。物品、数量、单位、备注、当前库存或差异等字段不得因业务类型变化把删除按钮挤到下一行；
- 入库明细依次展示物品、入库数量、单位、行备注和删除操作；
- 出库与调拨明细依次展示物品、当前库存、操作数量、单位、行备注和删除操作；
- 盘点明细依次展示物品、账面数量、实际数量、差异、单位、行备注和删除操作；差异由前端即时展示、服务端仍按当前库存重新校验；
- 桌面端同类输入控件高度一致；单位作为独立只读文本列，不得塞在数量输入框下方导致该列高度高于其他列；
- “关联原记录”使用正常字段宽度，帮助文字放在字段下方，不与选择器并排形成错位；
- 中等宽度允许一条明细按明确分组换成两行；窄屏将每条明细改为纵向信息卡。任何断点下删除按钮都必须保持在该明细自身的固定操作位置。

### 3.3 物品

- 使用查询列表和新增/编辑抽屉；
- 表格单元格默认只读；
- 物品编码创建后不可修改；
- 编辑字段为物品名称、基本单位和状态；
- 停用时说明“不能用于新的库存操作，历史记录仍会保留”；
- 支持从物品进入库存查询。

### 3.4 仓库与库位

- 使用仓库与库位主从布局；
- 桌面宽度下左侧选择仓库，右侧展示该仓库的库位；
- 仓库展示编码、名称、所属部门、状态和库位数量；
- 库位展示编码、名称、状态、库存种类和操作；
- 仓库或库位使用新增/编辑抽屉，不使用永久可编辑表格；
- 没有库位时展示“这个仓库还没有库位”及“添加第一个库位”。

### 3.5 库存记录

- 一个列表统一展示入库、出库、调拨和盘点记录；
- 支持按日期、业务类型、仓库和物品筛选；
- 列表使用记录编号、业务类型、物品、来源、目标、数量变化、经办人和发生时间等业务字段；
- 详情通过抽屉展示整单备注、行备注和明细；
- 旧记录不提供修改和删除入口；
- 纠正说明使用“重新办理盘点并关联本记录”，不暴露内部关联字段。

## 4. 仓储 Agent 交互位置

- Agent 启用且用户具有仓储查询权限时，宽屏使用右侧停靠侧栏；
- 侧栏可以收起为“仓储助手”轻量入口，收起不销毁当前会话；
- 中等宽度默认收起；窄屏使用覆盖式抽屉；
- Agent 未启用时不展示入口，也不保留假的占位区域；
- 正式开发只使用 SVG 图标组件，不把设计示意图裁切成运行时图标。

## 5. 文案规则

### 5.1 统一用语

| 禁止或旧用语 | 用户用语 |
| --- | --- |
| 主数据维护 | 物品、仓库与库位 |
| 人工操作 | 库存操作 |
| 库存流水 | 库存记录 |
| 操作单 | 入库单、出库单、调拨单、盘点单 |
| 纠错操作 | 关联原记录 |
| 新增明细 | 添加一行 |
| 刷新流水 | 刷新记录 |
| 版本冲突 | 数据已被其他人更新，请刷新后重新操作 |

普通用户界面禁止出现：`No Data`、`version`、`requestId`、`correctedOperationId`、字符串保存、精度处理、DO、DTO、API、CAS、数据库或框架名称。

### 5.2 状态文案

| 状态 | 标题 | 说明与动作 |
| --- | --- | --- |
| 首次无物品 | 还没有物品 | 先添加物品，才能办理入库和查询库存；动作“添加第一个物品” |
| 筛选无结果 | 没有找到符合条件的库存 | 建议更换条件；动作“清除筛选” |
| 加载失败 | 库存加载失败 | 说明当前不可用范围；动作“重新加载” |
| 调拨成功 | 调拨已完成 | 展示业务编号；动作“查看库存记录” |
| 库存不足 | 库存数量不足 | 说明物品、可用数量和请求数量，不允许提交 |
| 并发变化 | 库存已经发生变化 | 提示刷新当前库存后重新确认 |

空状态不能只显示空图标或“暂无数据”；错误不能使用空数组伪装成功。

## 6. 图标与图片规则

- 禁止 Emoji、表情、Unicode 字符或文字箭头冒充图标；
- 优先使用现有 `@element-plus/icons-vue`；
- 缺失业务图标使用项目本地正式 SVG；
- 同一层级保持一致的线宽、圆角、尺寸和线性/填充风格；
- SVG 必须有规范 `viewBox`，颜色使用 `currentColor`，并提供无障碍名称；
- 空状态插图如确有必要，使用本地、主题兼容的 SVG，不使用不受控外链；
- 设计示意图只用于布局和视觉验收，不作为页面背景或图标资源进入生产代码。

## 7. 主题规则

仓储模块必须同时适配现有默认、Ocean 和 Midnight 三套主题，不建立仓储专属配色。

| 用途 | 语义令牌 |
| --- | --- |
| 页面背景 | `--ui-page-bg` |
| 普通容器 | `--ui-surface` |
| 抽屉与浮层 | `--ui-surface-elevated` |
| 筛选区与表头 | `--ui-surface-muted` |
| 强调文字 | `--ui-text-strong` |
| 普通文字 | `--ui-text` |
| 辅助文字 | `--ui-text-muted` |
| 边框 | `--ui-border`、`--ui-border-strong` |
| 主操作 | `--ui-primary`、`--ui-primary-hover` |
| 状态 | `--ui-success`、`--ui-warning`、`--ui-danger` 及其 soft 令牌 |

仓储组件样式禁止写死主题背景、主文字、边框、主色和状态色。状态不能只靠颜色表达，必须同时展示文字或正式图标。

## 8. 响应式规则

- 宽屏：系统导航、仓储页面和可选 Agent 侧栏并存；
- 中等宽度：系统导航折叠，仓储入口使用紧凑导航，筛选条件允许换行，Agent 默认收起；
- 窄屏：筛选条件进入底部抽屉，库存表格改为信息列表，不压缩成不可读横向表格；
- 仓库与库位在窄屏使用“先选仓库，再查看库位”；
- 编辑抽屉在窄屏使用全宽；
- 移动端主要入口保留查询、操作、物品和记录，具体可见项继续按权限控制。

## 9. 交付验收

研发交付至少满足：

1. 库存查询、库存操作、物品、仓库与库位、库存记录五条真实用户路径可操作；
2. 入库、出库、调拨和盘点分别呈现正确字段和唯一主操作；
3. 首次无数据、筛选无结果、加载失败、提交成功、库存不足和并发变化均有明确状态；
4. 默认、Ocean、Midnight 三主题下完成同页面截图检查；
5. 常用桌面、中等宽度和窄屏下主任务无截断、重叠和不可读横向压缩；
6. 页面不存在 Emoji 图标、开发术语、英文空状态和直接暴露的内部字段；
7. 设计示意与浏览器实现进行同尺寸视觉对比，功能测试通过不能替代视觉验收；
8. Agent 默认关闭时仓储人工页面完整可用且不出现 Agent 占位。

## 10. 非目标

- 不新增采购、销售、库存预警、报表中心和导出；
- 不增加审批、草稿、复核和撤销流程；
- 不更换 Vue、Element Plus、路由或状态管理体系；
- 不增加第二套全局主题、图标库或通用后台框架；
- 不修改仓储后端业务规则、数据模型或接口语义；
- 不在本轮实现尚未就绪的 Agent 对话功能。
