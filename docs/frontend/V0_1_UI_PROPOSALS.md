# 0.1 前端页面与视觉方案

> 状态：已确认  
> 版本：0.1  
> 更新日期：2026-08-09
> 依据：[0.1 需求范围](../../requirements/V0_1_SCOPE.md)  
> 变更说明：保留已确认的 Minimal Tech 与双配色基线，同步已实现的两种主页布局、内容区块编辑及用户/角色删除交互，并将首次改密参数入口正式收窄为“登录安全”。

## 1. 页面范围

0.1只设置8个页面或主视图：

| 编号 | 页面 | 使用者 | 必须完成的任务 |
| --- | --- | --- | --- |
| P01 | 公开主页 | 匿名访问者 | 按已发布布局、配色和区块查看当前公开快照 |
| P02 | 内部登录 | 内部用户 | 提交账号密码并进入工作台 |
| P03 | 工作台 | 已登录用户 | 查看当前用户和有权限使用的功能入口 |
| P04 | 用户管理 | 管理员 | 查询、创建、编辑、软删除用户并分配角色 |
| P05 | 角色管理 | 管理员 | 查询、创建、编辑、引用校验删除角色并选择权限 |
| P06 | 主页内容管理 | 内容维护人员 | 编辑布局、内容区块与基础内容，上传图片、保存草稿、发布和撤回 |
| P07 | 主页预览 | 内容维护人员 | 使用公开主页展示组件查看当前草稿效果 |
| P08 | 登录安全 | 具有登录安全管理权限的管理员 | 只启用或停用首次登录强制改密 |

不单独创建部门、文件、审计、菜单、通用配置、字典和统计页面。“登录安全”是只维护 `force_password_change` 的专用例外，不得演变为通用参数页面。图片上传嵌入主页内容管理；发布与撤回审计由后端记录，不在0.1提供审计查询页。

## 2. 布局

### 2.1 公开布局

- 使用大留白、非对称首屏和明确的视觉焦点；
- 导航采用轻量悬浮结构，不使用传统后台式横条；
- 站点名称、简介、主图、联系方式与固定类型的内容区块共同构成公开内容；
- 支持 `GRID_SPLIT`、`BANNER_SPLIT` 两种代码定义布局，公开页只根据已发布快照渲染；
- 抽象光场、轨道或网格只承担氛围，不增加新的业务信息；
- 未发布或撤回时展示明确的不可用页面，不显示草稿内容。

### 2.2 登录布局

- 延续公开主页的科技视觉，但登录表单保持安静、清晰；
- 只包含品牌识别、账号、密码、登录按钮和错误反馈；
- 不增加注册、第三方登录、短信登录和找回密码入口；
- 登录成功后进入工作台。

### 2.3 系统布局

- 使用浮动导航和工作区，不再采用整块深色侧栏加白色内容区的传统结构；
- 导航只包含工作台、主页内容、用户、角色，以及按 `system:config:manage` 权限显示的登录安全入口；
- 主内容区减少层层卡片，主要依靠留白、细分隔和清晰排版建立层级；
- 表格、表单和错误状态以可读性优先，科技感不能降低管理效率；
- 移动宽度下导航转为紧凑顶部入口，内容改为单列。

## 3. 页面关键结构

### P03 工作台

只展示当前用户摘要和可访问功能入口，不增加统计卡片、趋势图、待办和通知。

### P04 用户管理

- 一个分页用户表格；
- 一个创建/编辑用户表单；
- 创建表单包含账号、显示名称、初始密码和角色；编辑表单不回显或重置密码；
- 部门固定为根部门，不展示部门选择器；
- 删除前显示“不可恢复”确认；初始化管理员或当前登录用户的删除请求由后端明确拒绝，前端不替代最终保护；
- 不提供导入、导出、批量操作、用户恢复和用户详情页。

### P05 角色管理

- 一个角色列表；
- 一个角色编辑表单；
- 权限从代码注册列表中选择；
- 删除操作使用二次确认；系统管理员角色在界面中不可删除，被有效用户引用的角色由后端拒绝并返回引用用户名；
- 不提供角色继承、数据范围和菜单配置。

### P06 主页内容管理

- 在一页内编辑站点名称、简介、主图、联系方式、代码定义的配色和布局；
- 可维护 `ABOUT`、`SERVICE`、`NEWS`、`CONTACT` 四种固定类型的内容区块：新增、编辑、删除、上移、下移，以及上传可选配图；
- 主图和区块配图上传后直接显示当前草稿图片；
- 操作区只包含保存草稿、预览、发布和撤回；配色和布局均属于草稿内容，不增加独立主题或布局管理入口；
- 草稿状态和当前公开状态必须分开显示；
- 不增加区块拖拽、模板选择、富文本编辑器、文件库和自定义区块类型。

### P07 主页预览

复用P01的主页展示组件，只替换为草稿数据和草稿配色，并增加“预览”标识。禁止维护第二套预览页面样式。

### P08 登录安全

- 页面名称和导航名称统一为“登录安全”，不得使用暗示通用能力的“系统设置”；
- 只展示和维护 `force_password_change` 开关，不提供参数新增、删除、键编辑或其他配置项；
- 页面和接口均要求 `system:config:manage`，前端隐藏入口不能替代后端鉴权；
- 开关修改失败时明确显示错误，不能用本地状态假装保存成功。

## 4. 视觉方向：Minimal Tech

该方向参考[Awwwards](https://www.awwwards.com/)常见的编辑式排版、留白和沉浸首屏，以及[GSAP](https://gsap.com/)强调的时序、缓动和连续动作表达；只吸收设计方法，不复制具体站点、素材或布局。

### 4.1 视觉原则

- 中性色作为主体，只保留一个高亮色用于状态、焦点和抽象视觉；
- 使用大标题、短文案、非对称构图和更舒展的间距，避免平均分栏和整齐堆盒子；
- 使用细网格、轨道、光晕和几何节点表达科技感，不使用廉价霓虹字、满屏渐变和无意义粒子；
- 导航、状态和操作采用轻量悬浮结构，圆角克制且不重复嵌套；
- 公开端可以更有表现力，内部管理端保持稳定信息密度和明确操作反馈；
- 公开端、登录页和内部端共享颜色、字体、间距与动效节奏，但不强行使用完全相同的布局。

### 4.2 配色能力

- 0.1提供两套代码定义配色：`GRAPHITE`（黑白）和 `AZURE`（蓝白）；两者共享同一组件树、布局和交互，只替换语义颜色令牌；
- 内容维护人员在主页内容管理中选择配色，选择结果与其他草稿字段一起保存；预览读取草稿配色，公开主页读取已发布快照配色；
- 配色发布遵守现有草稿与公开快照隔离规则，修改草稿配色不能立即改变线上页面；
- 内部系统的用户界面配色偏好与公开主页配色是两个独立状态。内部偏好由Pinia与 `localStorage` 保存；公开主页配色以草稿和发布API为权威来源，不能由Pinia或 `localStorage` 代替；
- 禁止增加任意颜色输入、主题表、主题市场、动态CSS/JSON配置和后台主题编辑器；新增第三套配色时必须作为新的明确需求，通过代码和版本控制加入。

### 4.3 内部系统微交互

内部系统使用CSS、Vue `<Transition>`和Element Plus已有过渡提供点击反馈，不使用GSAP编排。推荐基线如下：

- 普通按钮悬停和按压反馈控制在140—180ms；按压时只做约 `scale(0.98)` 的轻微压缩，释放后立即回到最终状态；
- 标签页与主导航使用180—220ms的滑动指示器表达选中位置，内容切换只使用透明度和约4px位移；
- 对话框与抽屉使用200—260ms的短时进入和退出，不让动画阻塞确认、取消或错误展示；
- 保存、发布等操作在点击后明确展示进行中、成功或失败状态，动画不能替代真实业务结果；
- 同类控件共享同一节奏和缓动，不为单个页面创建特殊动画；禁止全局 `* { transition: ... }`、表格逐行动画、持续循环和装饰性抖动；
- 所有微交互必须遵守 `prefers-reduced-motion`，减少动态时保留状态变化，但取消位移、缩放和非必要渐变。

### 4.4 GSAP动效边界

0.1只考虑GSAP核心包，不引入ScrollSmoother、Draggable、SplitText等插件。

允许的动效：

- 公开主页首屏标签、标题、简介、联系方式和主图依次进入；
- 登录页品牌区与表单形成一次短时序；
- 动画结束后页面保持静止，不依赖持续运动制造科技感；
- 动画只改变 `transform` 和 `opacity`，不参与业务状态和布局计算。

禁止的动效：

- 在工作台、用户、角色和内容管理页面使用GSAP编排；
- 滚动劫持、强制平滑滚动和长时间入场；
- 鼠标尾迹、全屏粒子、无限循环、持续闪烁和高频视差；
- 使用GSAP给表格行、表单字段、标签页和普通按钮编排动画；这些控件只使用上一节定义的CSS或Vue微交互；
- 用动画掩盖加载、失败或权限状态。

系统必须遵守 `prefers-reduced-motion`；减少动态时直接展示最终状态，不播放非必要动效。Vue组件使用局部 `gsap.context()` 管理作用域，并在卸载时执行清理；不建立通用动画注册中心。

## 5. 组件与实现边界

- Element Plus仍作为内部表格、表单、对话框和反馈组件的候选；
- 公开主页、品牌视觉和抽象图形使用普通Vue组件、CSS和必要的SVG；
- GSAP只由公开主页和登录页的实际使用组件引入，不挂载到全局启动层；
- GSAP只负责表现层时序，不进入路由、权限、数据请求和业务状态；
- 不逐个二次封装Element Plus基础组件；
- 不引入第二套UI组件库或第二套动效库；
- 视觉选择不能改变0.1页面和业务范围。

## 6. 已放弃方向

原方案A“稳健中后台”和方案B“清爽产品化”不再作为候选，也不能作为实现默认值。

## 7. 确认结论（2026-08-03）

1. **Minimal Tech 方向 + 双配色**——已确认：公开主页预留 `GRAPHITE`、`AZURE` 两套代码定义配色能力；
2. **内部微交互**：0.1 落地 **B 预设（克制现代）**为默认（进入约 250–280ms、退出约 150–180ms、位移 6–15px）；**A/C 预设预留修改口**——交互参数（时长/缓动/位移/按压反馈）定义为独立令牌与配置层，组件不硬编码数值；未来切换 A/C 只改配置层，不重构组件（A=稳妥直接、C=柔和灵动，数值未来再定）；
3. **Element Plus（2.14.3）正式采用**为内部管理端组件库——已确认（依据：素材库 `02-已批准/admin-ui-kit-v0.1`，EP 作为功能底座，视觉以已批准令牌为准）；
4. **GSAP 不引入 0.1**——公开主页首屏入场使用「首屏入场参考配方」（CSS/Vue Transition，无依赖实现同等效果）；
5. **8 个页面（P01–P08）范围确认**；`admin-ui-kit` 作为前端基座、按需引入组件（不默认搬入全部 18 个）；三套主题（石墨白/深海蓝/午夜黑）可切换；内部界面配色偏好与公开主页配色**分离**（内部偏好由 Pinia/localStorage，公开主页配色以草稿与发布 API 为权威）。“登录安全”只维护 `force_password_change`，不形成通用配置能力。
