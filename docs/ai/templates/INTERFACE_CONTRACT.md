# 接口契约差值核对（INTERFACE_CONTRACT）

> 状态：生效
> 用途：仅在**新建接口或实质改变既有接口**时，核对材料不能直接确定的差值；默认在当前对话和实现差异中完成，不生成永久接口文档。

## 1. 先核对事实，再询问差值

来源不存在绝对固定的先后，按问题语义选择权威来源并处理冲突：

| 来源 | 主要约束 |
| --- | --- |
| 已确认需求与业务规则 | 用户意图、业务必填、权限、状态流转和失败语义 |
| 既有外部契约与消费者 | 兼容边界、HTTP 行为、前后端类型和实际调用 |
| 服务端生成与处理逻辑 | ID、审计字段、默认值、派生字段以及条件必填 |
| DTO、Controller 与 OpenAPI | 当前实现的请求、响应、校验和安全入口 |
| Liquibase 与持久化模型 | 存储类型、长度、唯一性、可空性及默认值 |

数据库 `NOT NULL` 不自动等于请求必填：字段可能由服务端生成、由上下文补齐，或只在特定状态下必填。反之，数据库可空字段也可能因已确认业务规则而请求必填。材料冲突时先报告，禁止挑选方便实现的一方。

## 2. 只核对不能推导的差值

- 请求字段：业务必填与条件必填、长度/格式/枚举、服务端生成字段；
- 成功响应：消费者真正需要的字段、ID 字符串与时间格式；
- 失败语义：未登录、越权、不存在、重复、引用、并发和大小限制；
- 引用操作：有效引用的判定及需要向用户展示的引用对象；
- 前端对齐：表单标志、提交校验、错误展示和权限体验。

材料能够确定的内容直接按来源实现；确需用户决定的内容压缩为少量选择题。字段、HTTP 结构和当前精确文案由 DTO、Controller、生成的 OpenAPI 与测试维护，不在清单中复制。

## 3. 最轻记录方式

在当前回复中列出“已由材料确定 / 需要确认的差值 / 对应验证”即可。只有该判断本身成为长期业务需求或跨模块公共契约时，才写回对应需求或模块 `CAPABILITY.md`；禁止默认创建 `docs/system/api/<模块>/<接口>.md`、任务书或验收报告。

完成标准是代码、前端消费者、OpenAPI 和风险最近测试一致，而不是额外文档数量。
