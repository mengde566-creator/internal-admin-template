# 接口契约前置清单（INTERFACE_CONTRACT）

> 版本：0.1
> 状态：生效
> 用法：**每个接口（或一组相关接口）实现前**，AI 必须先填写本清单并对照，再写代码。
> 目的：让"字段校验、错误提示、前后端对齐"这些问题在**用户使用之前**被讨论和解决，
> 而不是等用户发现。这是需求漏斗的接口级延伸。
>
> **核心原则（材料驱动的裁剪）**：判断来源有优先级，**用户/项目已有的材料能推导的，AI 不问也不猜**——
> 材料越全，需要询问用户的越少。用户补充了材料（表结构、需求、原型），对应判断直接跳过。
>
> **示范文件**（验证本流程真实可用的完整样例）：
> - [创建用户契约清单](../../system/api/iam/USER_CREATE.md)
> - [创建角色契约清单](../../system/api/iam/ROLE_CREATE.md)
> - [删除用户契约清单](../../system/api/iam/USER_DELETE.md)
> - [删除角色契约清单](../../system/api/iam/ROLE_DELETE.md)

## 0. 推导来源优先级（先查材料，再推导，最后才问）

| 优先级 | 来源 | 能推导出什么 | 需要用户参与？ |
| --- | --- | --- | --- |
| 1 | **表结构（Liquibase 变更集，最高权威）** | `NOT NULL`→必填；`VARCHAR(n)`→长度上限；`UNIQUE`→唯一校验；`DEFAULT`→默认值；类型→格式（BIGINT/BOOLEAN/DATETIME） | 不需要 |
| 2 | **需求文档 / 已确认 REQ / 业务规则** | 业务必填与业务可空的差异、枚举值、格式（如邮箱）、状态流转 | 不需要（已确认材料） |
| 3 | **现有代码（DTO 注解、前端表单、相似接口）** | 实现层已表达的校验与文案惯例 | 不需要 |
| 4 | **问用户（仅限"差值"）** | 表结构/需求都看不出的**业务决策点**（如"联系方式必填还是可空"） | 只问差值，**选择题**形式 |

**判断规则**：
- 表结构 `NOT NULL` → 前端必填星号 + 后端 `@NotBlank`，**直接照抄，不讨论**；
- 表结构 `VARCHAR(64)` → 前端 `maxlength=64` + 后端 `@Size(max=64)`，**直接照抄，不讨论**；
- 表结构可空（无 NOT NULL）但业务上必须填 → 这才是**需要决策的点**，列入差值问用户；
- 表结构 `UNIQUE` → 创建/更新接口必须做重复校验并给出明确文案；
- 内部字段（password_hash、审计字段、deleted）**不进入任何请求/响应**，直接排除。

**差值清单**：契约清单只列"表结构看不出来"的部分（业务必填差异、错误文案、枚举展示、前端对齐点），
表结构能推导的直接标注来源（如 `必填：表结构 NOT NULL`），不用重复推导。

## 1. 必填清单（每个接口开发前逐项回答）

| 项目 | 要求 | 例子 |
| --- | --- | --- |
| 请求字段校验 | 列出每个字段：必填/长度/格式/枚举；后端 DTO 注解与前端表单规则**必须逐项一致** | `siteName` 必填、≤120 字 |
| 必填字段的前端标志 | 每个必填字段在前端必须有 `required` 星号标志 + 提交前校验 | el-form-item required |
| 错误提示文案 | 每个失败场景列出**明确文案**：缺什么、谁在用、为什么拒绝；禁止"操作失败""已被使用"这类无信息量文案 | "该角色正被用户 [张三、李四] 使用，请先解除分配后再删除" |
| 引用类操作 | 删除/停用/修改前被引用时，提示必须**点名引用方**（谁在用、几条）；引用校验必须考虑软删除等数据状态 | 角色删除列出用户名 |
| 敏感/边界行为 | 越权、未登录、不存在、重复、并发、大小超限各自的响应语义与文案 | 401/403/404 文案 |
| 前后端类型对齐 | ID 字符串、时间格式、枚举值、分页字段 | 19 位雪花 ID 一律字符串 |

## 2. 清单格式（直接复制到接口设计文档）

```markdown
### 接口：<路径>（<方法>）
- 请求字段：
  | 字段 | 必填 | 校验 | 前端对齐点 |
  | --- | --- | --- | --- |
  | name | 是 | ≤50 字 | 表单 required + maxlength |
- 成功响应：<结构要点>
- 错误场景与文案：
  | 场景 | 状态码 | 文案 |
  | --- | --- | --- |
  | 未登录 | 401 | 未登录或登录已失效 |
  | 名称重复 | 400 | 名称已存在：xxx |
  | 被引用 | 400 | 正被用户 [x、y] 使用，请先解除分配 |
```

## 3. 完成标准

- 清单在接口实现前填写完成；
- 后端 DTO 校验注解、前端表单规则、错误文案三者与清单逐项一致；
- 清单随接口文档保存（`docs/system/api/<模块>/<接口>.md` 或需求文档内），可被验收清单引用。
