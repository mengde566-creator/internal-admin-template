# 0.2 仓储前端专项修复（第二轮）

> 状态：已实施（历史专项，仅在排查对应前端回归时按需查阅）
> 前置：第一轮页面外壳、独立滚动与基础 Agent 展示已由项目负责人验收
> 范围：仅仓储前端布局、表格信息可达性与助手尺寸交互
> 禁止扩大：不修改后端、数据库、OpenAPI、AI Tool、Prompt、模型、SSE 或业务规则
> 后续统一治理：以 [V0_2_FRONTEND_INFORMATION_READABILITY.md](V0_2_FRONTEND_INFORMATION_READABILITY.md) 为当前执行入口

## 1. 本轮目标

在真实长数据、滚动和 Agent 展开状态下，完成仓储五个入口的整体排查，修复：

1. 表格“操作”固定列滚动时覆盖正文、错位或悬浮在错误位置；
2. 长编码、名称、位置和记录编号被省略后无法查看完整内容；
3. 仓储助手默认宽度不足，长回复、表格和库存卡片难以阅读，且用户不能调整大小；
4. 修复同一机制在库存查询、物品、仓库与库位、库存记录及详情抽屉中的同类问题。

本轮不重新设计仓储页面，不新增业务功能，只让已有信息完整可达、布局稳定、操作可靠。

## 2. 已确认问题

### P0：固定操作列覆盖和滚动错位

- 库存查询和库存记录使用 Element Plus `fixed="right"` 操作列；业务区变窄或表格横向/纵向滚动时，固定列可能覆盖相邻正文。
- 库存记录长编号、位置和时间会换成多行，固定列与正文行高、阴影和层级组合后出现视觉覆盖。
- Agent 展开、收起或调整宽度后，表格可用宽度变化，不能依赖首次渲染尺寸。

要求：

- 逐页检查所有表格、详情表格和抽屉表格，不只修截图中的两个页面；
- 宽度充足时可以保留固定操作列，但必须保证背景、边界、行高和点击区域不覆盖其他列；
- 宽度不足时应取消固定列、启用表格内部横向滚动或切换已有移动信息卡，禁止继续强行固定；
- Agent 展开、收起和调宽后，表格必须重新获得正确布局；禁止用延迟、刷新页面或硬编码 margin 掩盖问题。

### P0：省略信息不可恢复

- 物品编码与名称、仓库、库位、记录编号、来源/目标位置等字段存在省略号；当前并非所有字段都能查看完整值。
- 原生 `title` 不能作为唯一方案：键盘操作、移动端点击和长内容阅读体验不足。

要求：

- 允许保留省略号控制表格密度，但每个被截断字段必须能查看完整内容；
- 桌面端支持鼠标悬停和键盘聚焦查看完整文本；移动端支持点击展开或进入已有详情；
- 完整文本必须可选择或复制，不得只显示几秒即消失且无法操作；
- 未截断字段不必显示多余浮层；禁止把所有列改成无限换行导致表格再次失控；
- 使用现有 Element Plus 能力或当前页面局部组件，不引入新依赖，不建设全局表格框架。

### P1：仓储助手尺寸不可调

- 当前助手宽度不足以承载长回复、Markdown表格、库存卡片和历史列表；窄面板会造成大量断行和阅读负担。
- 用户只能展开或收起，不能按当前任务调整阅读空间。

要求：

- 桌面 DOCKED/OVERLAY 模式提供清晰、可操作的水平调宽能力；建议默认宽度约 `420px`，最小约 `360px`，最大不超过工作区可用宽度的 `55%` 且设合理像素上限；最终数值以真实页面走查为准；
- 调宽使用明确拖拽手柄，并提供无障碍名称和键盘可操作方式；不能只有难以发现的 1px 热区；
- 调整后的宽度在仓储子路由切换期间保持，刷新后持久化不是本轮必需；
- 用户扩大助手时，不得把业务区压到表格不可用；空间不足应转为 OVERLAY，不能同时破坏两边；
- DRAWER/窄屏保持全宽抽屉，不提供无意义的拖拽；
- 助手内部继续保持头部、消息区、历史区和输入区各自正确滚动，调宽不得产生外层页面滚动或抖动。

## 3. 排查范围

必须检查以下真实页面及其详情/抽屉：

- `/warehouse/stock`：库存筛选、库存表格、固定操作列、长物品与库位；
- `/warehouse/operations`：四类操作表单、多明细、长选项文本；
- `/warehouse/items`：物品列表与编辑抽屉；
- `/warehouse/locations`：仓库/库位主从列表及抽屉；
- `/warehouse/records`：长记录编号、物品、来源/目标、时间、固定操作列和详情抽屉；
- `WarehouseAgentPanel`：历史列表、长回复、管道表格、库存卡片、输入区和尺寸调整。

只修复具有同一根因或真实复现证据的问题。不得借“大排查”重写无问题页面。

### 同类问题排查要求

本轮不是再次只修项目负责人指出的截图位置。研发必须先按机制排查，再逐页确认结果：

- 搜索仓储前端全部 `fixed="right"`、`position: fixed/sticky/absolute`、横向滚动容器、`overflow`、`text-overflow: ellipsis` 和固定/最小列宽；
- 对每处操作列检查表头、正文、斑马纹背景、阴影、行高、点击区域和横向滚动边界，包含主表格与详情抽屉表格；
- 对每处省略文本确认完整内容入口，而不是只检查库存页已经加过 `title` 的字段；
- 对每个仓储入口分别验证 Agent 关闭、默认宽度、最小宽度、最大宽度以及展开/收起后的布局；
- 对同一组件验证短数据、长数据、单行、多行、空状态和加载状态，避免只在当前演示数据下成立；
- 修复一个公共根因后，必须回到五个入口重新走查，不能因为修改发生在共享CSS或通用组件中就推断其他页面自动通过。

交付回报必须提供一份紧凑排查结果，逐项写明“页面/组件、发现的问题、根因、是否修改、验证方式”。没有发现问题的页面也要写明实际检查过的状态，禁止仅列修改文件。

## 4. 实现边界

允许修改：

- `frontend/src/modules/warehouse/**` 中直接相关页面、组件和测试；
- 第一轮涉及的仓储工作区布局文件，仅限尺寸联动确实需要的最小改动；
- 必要的最小前端 E2E 或组件回归测试。

禁止修改：

- 所有后端、Liquibase、数据库数据和部署文件；
- API字段、生成类型、Agent工具、Prompt、模型回复和卡片协议；
- 全局主题系统、路由架构、Element Plus版本或依赖；
- IAM、主页、登录和角色页面；
- 新建通用表格框架、全局Tooltip框架、状态管理或第二套CSS令牌。

所有颜色继续使用现有语义令牌；所有图标使用现有正式SVG或Element Plus图标，不使用Emoji。

## 5. 验收矩阵

### 尺寸和状态

- `1440×900`：左导航展开；Agent关闭、默认宽度、最小宽度、最大宽度；
- `1280×800`或实际常用中屏：Agent展开并调宽；
- `1024×900`：OVERLAY/DRAWER边界；
- `390×844`：移动信息卡与全宽助手；
- 默认、Ocean、Midnight三套现有主题。

### 数据

- 长物品编码和名称；
- 长仓库/库位组合；
- 长记录编号、来源/目标和备注；
- 库存记录不少于10行；
- Agent至少两轮长回复，包含表格和库存卡片；历史对话不少于10条。

### 必须证明

1. 各表格滚动前后无正文被操作列覆盖、无表头/行错位、无操作按钮点击穿透；
2. Agent展开、收起和调宽后，表格立即保持正确布局；
3. 每个实际发生省略的业务字段都能通过鼠标、键盘和移动端适用方式查看完整内容；
4. 完整内容可选择或复制，且不会被其他浮层裁切；
5. 助手宽度可调，最小/最大边界有效，调宽时页面无抖动、无文档级滚动条变化；
6. 长回复、表格和卡片只在助手消息区内部滚动，输入框始终可达；
7. 仓储五入口逐页真实走查，不能只用空数据或组件存在性测试代替；
8. 前端定向测试、全量单测、typecheck、build和`git diff --check`通过。
9. 固定操作列必须形成跨页面回归证据，至少覆盖库存查询、库存记录及一个详情/抽屉表格；不能只对单个截图坐标写样式断言。
10. 省略信息必须形成字段清单和交互回归证据，证明新增长字段时不会再次出现“看得到省略号、看不到全文”。

## 6. 交付要求

- 由一个研发角色在当前前端范围内端到端完成，不拆分新的设计、测试和验收流水线；
- 先用真实页面复现并记录根因，再做最小连贯修复；不得用临时 margin、固定截图尺寸或强制刷新解决；
- 回报列出逐页检查结果、实际修改文件、真实浏览器尺寸和剩余限制；
- 不得仅以“测试通过”宣称视觉问题解决；至少保留1440、1024、390三档关键截图。
