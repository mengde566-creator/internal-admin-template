## 1. 阶段目标

在创建前后端工程和数据库表之前，形成可实现、可验收、状态明确的0.1需求基线。

本阶段可以提出表结构和页面候选方案，但确认前不得编写Liquibase变更集、DO、Mapper或业务代码，也不创建空Maven模块和占位页面。

## 2. 已确认基线

- 产品面向独立开发者，用于快速派生包含公开展示端和内部管理端的完整项目；
- 0.1只验证“登录—编辑主页—上传图片—草稿—预览—发布—匿名查看—撤回”这一条闭环；
- 后端采用Java 25 LTS、Spring Boot 4.1.x、Maven多模块和模块化单体；
- 后端分为基础模块、IAM、文件、站点、最小审计和应用装配模块；
- 数据访问采用MyBatis-Plus，结构变更只通过Liquibase；
- 未配置外部数据库时使用本地SQLite；0.1不承诺其他数据库的完整兼容验证；
- 前端采用单个Vue 3、TypeScript、Vite SPA；
- 公开站点、内部工作台和管理控制台由布局、路由和权限区分；
- 公开主页使用两种代码定义布局、`GRAPHITE`（黑白）与 `AZURE`（蓝白）两套代码定义配色，以及四种固定内容区块类型；不建设主题编辑器；
- 公开主页配色随草稿和公开快照保存；内部界面配色偏好与公开主页配色状态分离；
- 管理端使用克制的CSS、Vue和组件库微交互；GSAP仅用于公开主页和登录页的一次性入场；
- 内部员工与管理员共用登录入口，0.1使用服务端Session；
- IAM只预置根部门、系统管理员角色和初始化管理员；管理员可以维护用户、角色并通过角色授权，用户软删除、角色引用校验删除；
- 0.1不建设部门管理、岗位、数据范围、动态菜单、账号安全扩展、通用参数配置、字典和完整审计平台；
- Spring AI、Python、Spring Cloud和外部客户账号均不进入0.1。

## 3. 最终落地方案

### 3.1 表结构

[0.1基础表结构方案](../database/V0_1_SCHEMA_PROPOSAL.md)已确认并落地为12张业务表：IAM（含首次改密参数）、文件、主页草稿/发布快照、草稿/发布区块快照和最小审计。布局、配色与区块类型均为代码定义枚举，不增加主题、模板或类型表。

### 3.2 前端

[0.1前端页面与视觉方案](../frontend/V0_1_UI_PROPOSALS.md)已确认并落地；页面范围为7个页面或主视图，采用 Minimal Tech、双配色、两种固定布局和内容区块编辑。

## 4. 已完成决策

以下四项均已确认并在实现中落地：

1. 采用12张表，以及“当前草稿表 + 当前发布快照表 + 两张区块快照表”的模型；
2. 在已确认Minimal Tech和两套配色能力的基础上，确认微交互强度，并决定是否采用Element Plus和GSAP核心包；
3. 确定本地图片存储根目录、允许类型、大小限制和公开访问规则；
4. 确定本地与CI共用的构建、类型检查、迁移检查和测试命令。

模板上游升级、第二个业务功能、外部数据库完整兼容和长期产品模块不阻塞0.1，不在本阶段展开。

## 5. 需求阶段退出条件

只有同时满足以下条件，才进入工程骨架和实现阶段：

- `requirements/V0_1_SCOPE.md`保持“已确认”；
- 后端模块边界和最小IAM边界已经确认；
- 0.1表结构已经明确确认；
- 本地文件规则已经明确确认；
- 前端视觉方向和组件库已经明确确认；
- 本地与CI质量命令已经明确确认；
- 未确认内容不会被默认实现、占位或兜底。
