# 0.2 仓储页面与 Agent 侧栏前端专项修复

> 状态：待实施
> 范围：仅前端布局、响应式与展示体验
> 禁止扩大：不修改后端、HTTP API、数据库、AI Tool、Prompt、模型配置或模块架构

## 1. 专项目标

修复仓储页面在 Agent 展开后出现的整页滚动、滚动抖动、业务区被过度压缩、表格与筛选控件错位，以及聊天侧栏难以阅读和操作的问题。

本专项只让现有功能在真实页面中稳定、清晰、可用，不新增业务能力，不重新设计仓储业务流程，不更换前端技术栈。

## 2. 已确认问题

### P0：页面滚动结构错误

- 当前浏览器文档承担整页滚动，顶部栏、左侧导航、仓储业务区和 Agent 侧栏处于同一滚动链。
- Agent 面板会撑高整个文档；业务内容较短时，向下滚动后左侧出现大片空白，右侧仍显示聊天内容。
- 文档滚动条出现或消失会改变可用宽度，Element Plus 表格固定列随之重新计算，产生横向抖动和错位。
- 顶部栏和左侧导航虽然使用 `sticky`，但仍参与文档滚动计算，不是稳定的应用外壳。

### P0：DOCKED 模式压坏业务页面

- 仓储工作区固定预留约 `320–380px` 给 Agent。
- 库存表格列的最小宽度合计约 `830px`；在 1440px 浏览器、左侧导航展开时，业务区实际宽度不足。
- 结果包括：物品编码被裁切和强制断行、筛选下拉框缩成窄块、固定操作列覆盖正文、表头与数据列错位。
- 当前响应式只看浏览器 viewport，例如库存页仅在 `<=720px` 切换卡片；它没有感知被 Agent 压缩后的真实容器宽度。

### P1：Agent 侧栏内部结构不便使用

- 最近对话长期展开，占用消息区高度；顶部和历史区重复出现“新话题”。
- 面板、历史、消息和输入区的滚动职责不清晰。
- 输入区没有形成始终可达的稳定底部区域。
- 对话名称全部是“对话 · 时间”，在大量历史记录下辨识度低；本专项不新增后端标题字段，只收敛列表占用。

### P1：助手消息展示不适合窄侧栏

- 模型返回的 Markdown 表格和 `**加粗**` 当前按纯文本展示，出现大量 `|`、星号和断行。
- 长文字与结构化库存卡片重复，占用大量纵向空间。
- 前端不能伪造、补写或修改模型回复含义，也不能把截断回复伪装成完整内容。

## 3. 目标页面骨架

```text
浏览器视口（不滚动）
├─ 左侧主导航（固定高度）
└─ 右侧应用区
   ├─ 顶部栏（固定）
   └─ 系统内容区（占满剩余高度）
      └─ 仓储页面
         ├─ 仓储标题与入口导航
         └─ 工作区（占满剩余高度）
            ├─ 业务内容区（独立滚动）
            └─ Agent 面板（独立滚动）
```

必须满足：

1. `html/body/#app` 不产生业务页面滚动；应用外壳固定为视口高度。
2. 左侧导航和顶部栏滚动前后位置不变化。
3. 业务内容区滚动时，Agent、顶部栏和左侧导航不移动。
4. Agent 消息滚动时，业务内容区不移动。
5. 使用稳定滚动条槽位，避免滚动条出现时页面宽度跳变。
6. 所有 flex/grid 滚动子项补齐 `min-height: 0`、`min-width: 0`，滚动只发生在指定容器。

## 4. Agent 展示模式

模式判断必须基于仓储工作区的真实可用宽度，不能只使用 `window.innerWidth`。

- **DOCKED**：仅在“业务区不少于约 860px，且 Agent 与间距仍可完整容纳”时使用；建议工作区可用宽度至少约 1280px。
- **COMPACT/OVERLAY**：空间不足以同时容纳业务区和 Agent 时，Agent 以悬浮面板覆盖在右侧，不压缩业务内容；可以随时收起。
- **DRAWER**：窄屏使用抽屉；不改变底层业务页面宽度。

禁止为了保持 DOCKED 而把业务页面压缩到不可用宽度。

## 5. 仓储业务区响应式规则

### 筛选区

- 使用明确的 CSS Grid 轨道，不依赖 `inline form` 自由挤压。
- 容器较宽时横向排列；中等宽度自动形成两行；窄容器使用单列或现有筛选抽屉。
- 物品选择器应优先获得宽度；仓库、库位和按钮不得缩成图标宽度。

### 库存结果

- 响应式依据库存页容器宽度。
- 容器能完整承载表格时显示桌面表格。
- 容器不足时切换现有库存信息卡，不得继续压缩固定列。
- 如保留表格横向滚动，滚动只能发生在表格容器内部；固定操作列不得覆盖其他列。
- 长编码允许省略并提供完整可访问文本，不允许逐字符断行或裁掉主要内容。

其他仓储子页只检查是否受同一布局机制影响；没有实际错位证据的页面禁止借机重写。

## 6. Agent 面板内部布局

- 面板高度取当前工作区可用高度，不再使用会撑高页面的固定 `min-height: 620px`。
- 头部固定在面板顶部，仅保留一个“新话题”入口。
- 最近对话默认只展示少量记录或折叠入口；完整列表在面板内部展开和滚动。
- 消息区使用剩余空间并独立滚动；切换对话或收到新消息时遵守既有滚动位置语义。
- 输入区固定在面板底部，不被长消息或历史列表推出可视区。
- Agent 展开、收起和模式切换不得改变外层页面高度。

## 7. 消息与卡片展示

- 结构化库存卡片继续使用现有受控 DTO，不改变卡片协议和动作白名单。
- 卡片在窄侧栏中保持业务名称、仓库、库位、数量和单位可读，不显示内部 ID。
- 普通文本支持安全、有限的可读格式：段落、换行、列表和加粗标记；禁止 `v-html`，禁止引入新的 Markdown 运行时依赖。
- 若实现表格格式化，只处理结构明确的管道表格并转为可横向滚动的本地展示；解析失败必须回退为安全纯文本。
- 长回复可以提供“展开全文/收起”，但不得删除、改写或伪造模型内容。
- 本专项不修改 Prompt，因此“减少模型生成重复表格”不属于本次前端完成条件。

## 9. 验收矩阵

### 必测尺寸

- 1440×900，左侧导航展开，Agent 展开；
- 1440×900，左侧导航收起，Agent 展开；
- 1024×900；
- 390×844。

### 必测内容状态

- 库存查询有结果且包含长物品编码；
- 最近对话不少于 10 条；
- 当前对话至少两轮，包含长回复和一张库存卡片；
- Agent 展开、收起及从 DOCKED/OVERLAY/DRAWER 切换。

### 机械断言

1. `document.documentElement.scrollHeight === document.documentElement.clientHeight`，页面外壳无业务滚动。
2. 滚动业务内容后，顶部栏和左侧导航的 `getBoundingClientRect()` 保持稳定。
3. 滚动 Agent 消息后，业务内容区 `scrollTop` 不变化；反向亦然。
4. 页面和仓储工作区无意外水平溢出。
5. 1440px＋左侧导航展开＋Agent 展开时，库存筛选控件完整可见，表格无覆盖和逐字符断行。
6. Agent 输入框始终可见；历史列表和消息列表不会共同撑高页面。
7. 默认主题及现有其他主题只使用语义令牌，无新增硬编码颜色。
