# SLICE-06 文件导入、影响预览与导出实施方案

> 状态：待研发派发
> 版本：0.1
> 需求事实源：[`requirements/V0_2_FILE_IMPORT_EXPORT.md`](../../requirements/V0_2_FILE_IMPORT_EXPORT.md)
> 更新日期：2026-09-01
> 边界：本文只固定实施责任、任务顺序、技术选择和验收边界；精确 HTTP 字段、表字段和页面组件由对应研发任务依据已确认需求及现有契约最小设计，并通过 OpenAPI、迁移和真实消费者保持一致。

## 1. 结论

SLICE-06按六个中型任务推进：两个共用基础、两个物品产品链、两个知识产品链。每个任务必须形成独立、可见且可回归的用户结果；前端随所属产品链交付，不建立最后统一补页面的任务。周期分析和助手文件入口不编号、不实施。

不新建“通用导入平台”业务模块。现有模块按数据所有权承担职责：

- `module-file`：受控文件本体、真实格式与结构安全、授权读取、到期物理文件清理；不知道物品行、知识版本或发布状态。
- `module-iam`：固定的导入限制配置组与权限目录；不知道作业内容或业务结果。
- `module-warehouse`：物品导入作业、解析后的业务行、影响预览、确认事务、模板及数据导出；不访问Knowledge内部表。
- `module-knowledge`：知识草稿、文档解析结果、版本、Embedding和ACTIVE发布；不访问Warehouse内部表。
- `module-audit`：复用窄审计入口记录关键操作摘要，不承载逐行导入事实。
- `app-server`：装配模块和迁移，不承载解析、导入或发布业务规则。

## 2. 已复核技术选择

### 2.1 Office与CSV

- `.xlsx`和`.docx`使用同一锁定版本的Apache POI `poi-ooxml`，首选当前官方稳定版5.5.1；该版本已修复旧版OOXML重复ZIP条目歧义风险。研发引入前仍须用项目依赖树和许可证检查确认传递依赖，不取SNAPSHOT。
- `.csv`使用Apache Commons CSV稳定版1.14.1，按固定UTF-8策略及受控Excel/RFC4180格式解析；不使用网站显示的1.14.2-SNAPSHOT。
- `.md`和`.txt`使用JDK字符流与项目现有能力，不增加Markdown渲染/执行引擎；只做确定性文本和章节解析。
- 不引入Apache Tika、LibreOffice、PDFBox、OCR、病毒扫描、CDR、消息队列、工作流引擎或第二套文件存储框架。

### 2.2 安全执行

- Office文件是ZIP/XML容器。必须在进入POI业务解析前检查实际容器类型、重复条目、条目数、单条与总展开大小、压缩比、加密、宏、OLE嵌入、外部关系和非法XML结构；POI自身限制继续作为第二层，不替代应用硬限制。
- 不计算或执行Excel公式。模板导入只接受文本、布尔或可安全转换的标量值；公式单元格按需求判为明确异常，不使用缓存公式结果冒充原值。
- 首期解析在应用进程中执行，但必须有文件/展开/行列/字符/时间硬边界和有界执行器，队列满时明确拒绝。POI官方说明库本身不能完全隔离恶意文件影响，因此本期不能宣称沙箱或病毒安全。
- 原文件不置于Web根目录；下载只通过授权处理器。用户下载原Office文件时页面必须继续标明“系统只完成格式与结构校验，未进行病毒扫描”。

### 2.3 作业和事务

- 共用“作业”仅指一致的身份、归属、文件、限制快照和基础状态语义；物品行、知识章节、业务状态和最终事务分别由Warehouse/Knowledge拥有，禁止建立万能JSON作业表或跨模块共享DO。
- 上传、解析、预览和确认是多个短请求；大文件解析不得占用数据库写事务。物品最终确认是Warehouse单库短事务；Knowledge向量生成在事务外，完整后才短事务切换ACTIVE。
- 状态推进使用当前状态+修订号CAS；执行接口使用`clientRequestId`幂等。应用重启发现没有可证明成功的处理中作业时，必须收口为可见失败或重新处理状态，不猜测完成。

## 3. 六个中型研发任务

### 06A：受控文档文件与导入限制配置

#### 用户结果

- 系统管理员在专用“导入限制”页面查看和修改固定配置项；每项有单位、允许范围和影响说明。
- 获得业务权限的调用方可以把本期允许格式存入受控隔离区；伪装、损坏、超量、加密、宏、外部关系、嵌入对象和危险容器在业务解析前被拒绝。
- 文件元数据可由后续Warehouse/Knowledge作业通过窄API恢复；到期且未被业务保留的文件按有界任务清理。06A本身不建立用户可见导入作业或独立文件管理页面。

#### 责任与范围

- `module-file`扩展为受控业务文档存储，但保持图片旧合同不变；文档只通过新的窄公开API供Warehouse/Knowledge创建和读取，业务模块不接触磁盘路径。文档API不复用通用`file:manage`替代业务授权：Warehouse/Knowledge在各自入口校验`warehouse:master:manage`/`ai:knowledge:manage`后，以服务端受信调用用途和操作者身份调用文件API；文件模块再次校验文件归属和用途。
- `module-iam`增加固定、类型化的导入限制配置合同和专用页面消费者；不能复用当前任意字符串更新而跳过类型与硬上限校验，也不建立任意key/value配置中心。
- 更新权限、OpenAPI、生成类型、app-server装配、正式/测试迁移master、能力包和直接测试。

#### 禁止

- 不创建物品或知识作业；不解析业务行和章节；不调用Embedding；不提供匿名读取；不声明病毒扫描。

#### 验收重点

- 真实格式和扩展名/MIME交叉校验；OOXML危险结构；字节/展开/条目/时间边界；失败文件清理；跨用途/跨用户读取；受信调用方权限形状；配置快照读取、硬上限、并发修改；旧图片上传和site引用回归；SQLite与正式目标数据库迁移兼容。

### 06B：物品模板、解析与影响预览

#### 用户结果

- 用户在物品页面下载标准模板或导出当前筛选物品，编辑后上传；标准模板无需列映射，系统直接展示新增、修改、停用、不变化、无效和冲突数量。
- 用户只处理真实异常，可修正允许的输入或排除行；错误报告可下载后重新上传。

#### 责任与范围

- `module-warehouse`拥有物品导入作业、行、预览和导出事实；通过`module-file`窄API读取受控文件。
- 只支持单个可识别数据表；标准列名和已确认的少量别名由服务端固定。物品编码是唯一定位键，名称不参与更新绑定。
- 实际物品规则必须由Warehouse生产Service提供批量预检窄能力或复用同一内部规则，禁止在解析器复制“单位可改/可停用”等第二套规则。
- 页面与HTTP合同随本任务完成，包括分页摘要、异常处理、刷新恢复和错误报告；生成OpenAPI类型，不手写平行前端类型。

#### 禁止

- 不执行最终物品写入；不支持仓库、库位、库存和人员映射；不调用模型猜表头；不逐行查询物品/库存/流水形成N+1。

#### 验收重点

- 标准路径不出现映射页面；列乱序、稳定别名、多余列；缺列、重复编码、重名、公式、隐藏/合并、多表歧义；分页预览；CSV编码和公式注入；服务端范围与权限；大量数据的有界批量查询；刷新恢复与结果过期。

### 06C：物品确认、原子执行与结果恢复

#### 用户结果

- 用户在最终摘要二次确认后，整批物品一次生效；双击或重复请求不重复写入。
- 确认前数据、权限、库存或流水事实发生变化时，整批零写入并提示重新预览；完成页显示真实结果并可返回物品列表核对。

#### 责任与范围

- `module-warehouse`实现预览修订、确认幂等、状态CAS、确认时批量事实复核和单事务批量执行。
- 复用现有物品编码不可变、基本单位、停用、版本CAS、审计和`WarehouseItemChangedEvent`语义；批量路径不能直接调用Controller，也不能循环调用带独立事务的公共方法造成部分提交。
- 执行成功后为实际变化物品发布一致事件；事件/索引失败语义按当前事务后事件合同处理，不把索引异步状态伪装成物品事务失败。

#### 禁止

- 不允许部分成功、自动重试业务冲突、跳过新冲突、撤销已完成导入或直接修改库存。

#### 验收重点

- 两个确认者竞争、同`clientRequestId`幂等、旧修订、权限变化、单位/库存/流水变化、数据库/审计异常全批回滚；SQLite单写者；MySQL/PostgreSQL/Oracle共同事务SQL；完成后列表与Warehouse语义搜索索引最终一致。

### 06D：知识资料草稿与确定性预览

#### 用户结果

- 知识维护人员上传`.docx/.md/.txt`，看到标题、章节、字符与片段摘要、忽略内容和相对当前ACTIVE的变化；可保存草稿，旧ACTIVE继续供助手回答。
- 相同文档版本内容重复上传保持幂等；同版本不同内容明确冲突。

#### 责任与范围

- `module-knowledge`拥有知识导入作业、草稿、解析章节、来源与版本预览；通过`module-file`窄API读取文件。
- DOCX确定性提取段落、标题、列表和表格可见文本；MD/TXT不执行HTML、脚本或Markdown扩展。文档编码、版本和标题使用业务输入，内部ID由服务端生成。
- 现有固定synthetic导入继续存在且不被用户上传入口改变；用户资料必须有独立来源类型，草稿不进入现有查询、目录和全文读取。
- 同任务交付知识管理页、草稿列表/详情、版本差异、来源文件受权下载和刷新恢复。

#### 禁止

- 不调用Embedding、不切换ACTIVE、不让Agent读取草稿、不做在线编辑器、PDF/OCR或模型改写。

#### 验收重点

- 三种格式稳定解析；提示注入正文；表格/标题/空段落；超量和截断；加密/宏/外部关系继承06A拒绝；相同内容幂等、内容冲突、当前版本变化；普通仓储用户不能读草稿或原文件；旧synthetic目录与问答不变。

### 06E：知识Embedding、原子发布与当前版本一致性

#### 用户结果

- 用户二次确认后，新知识版本完成索引并成为当前版；目录、具体问答和完整资料统一引用新版本。
- Provider或数据库失败时旧版继续可用，新版不部分出现；用户看到可重试的明确失败。

#### 责任与范围

- `module-knowledge`将现有固定synthetic摄取能力收敛为同一内部版本/向量写入主路径，但保留固定样本入口的服务端登记约束，不增加任意正文接口。
- 发布前重新校验权限、草稿、文档当前版本、内容hash和限制快照；Dense/Sparse Embedding继续使用已确认DashScope合同和批次上限。
- 所有向量成功后才进行短事务版本写入和ACTIVE切换；查询、目录和全文读取改为按来源授权返回ACTIVE，不能简单删除`synthetic=true`过滤。
- 页面展示发布进度、失败、重试和历史版本；发布确认仍为同一`ai:knowledge:manage`权限，不建审批流。

#### 禁止

- 不自动发布、不在数据库事务中调用Provider、不修改模型/维度/阈值、不重跑03E/04A质量Gate作为日常发布、不让失败新版进入检索。

#### 验收重点

- 多批Embedding中间失败、响应形状错误、维度/稀疏结构错误、数据库失败、并发发布、重复确认和同内容重发；Provider调用预算；旧ACTIVE持续服务；成功后SEARCH/LIST_ACTIVE/READ_ACTIVE与Agent引用统一；synthetic与用户资料来源标签正确。

### 06F：生产恢复、安全容量与两条用户链集成验收

#### 用户结果

- 物品和知识两条页面主链在刷新、重登、重复点击、过期、并发、服务重启、无权限和基础设施故障下都给出准确状态和可执行恢复方式。
- 系统管理员可以看到并调整固定限制；到期作业和文件被有界清理，已生效物品和知识不受影响。

#### 责任与范围

- 本任务只修复06A～06E集成时发现的真实差值，不新建第二套作业、状态或通用框架。
- 完成两条真实浏览器用户链、正式迁移组合、OpenAPI漂移、模块边界、清理和容量证据；按项目支持边界覆盖SQLite业务库，并对MySQL/PostgreSQL/Oracle业务作业迁移和关键SQL取得对应证据；Knowledge仍使用PostgreSQL/pgvector。
- 若进程内Office解析在已确认硬限制下仍无法满足可恢复性或稳定性，必须带失败证据退回负责人决定是否增加隔离解析进程；不得在本任务自行引入微服务、容器沙箱或新运行平台。

#### 禁止

- 不新增业务场景、格式、OCR、病毒扫描、助手入口、周期分析或导入审批；不以全量测试数量代替真实用户链。

#### 验收重点

- 真实浏览器完成模板下载→上传→预览→异常处理→确认→列表核对，以及知识上传→草稿→发布→知识查询核对；401/403、CSRF、跨用户作业、原文件下载提示、配置变化、重启残留状态、存储/数据库/Provider失败、清理与孤儿文件；提交前完整差异和依赖许可检查。

## 4. 顺序与依赖

```text
06A
 ├─ 06B → 06C
 └─ 06D → 06E
06C + 06E → 06F
```

- 06A是共同前置，先证明安全文件和配置合同，不夹带业务功能。
- 06B/06C和06D/06E在文件、迁移和前端路由能够隔离时可以并行；共享OpenAPI、权限目录、app-server聚合和父POM由同一主责协调，避免共享工作区覆盖。
- 每个任务由一个研发主责端到端完成实现、直接测试和最近用户链，不建立研发→测试→运维固定流水线。
- 任何任务发现需新增格式、改变权限模型、允许部分成功、增加扫描服务或隔离运行平台时，停止并返回产品/架构决策，禁止研发自行补猜。

## 5. 派发门槛与止损

每个任务派发前必须给研发同一份最小信息：对应需求编号、用户已知信息、真实操作、最终可见结果、状态/数据边界、禁止项、允许文件范围和机制特异性验收。任务内部的命令、fixture、定位器和范围内缺陷由研发一次最小修正，不升级为新分片。

满足以下任一条件立即做成本止损复核，而不是继续堆整改：

- 同一用户链第三次被退回；
- 实际验证轮次超过任务预计两倍；
- 新增治理/证据文件多于生产与测试变更；
- 为通过安全验收开始引入未确认的进程、服务、依赖或新状态机；
- 正常用户仍需逐列、逐行进行无业务价值操作。

## 6. 实施前剩余工程决定

以下不再需要项目负责人作产品选择，由研发在06A中依据真实基线提出最小实现并由总设计师复核：

1. 配置默认数值和代码硬上限：先以真实代表文件做内存、耗时和磁盘基线，再冻结；不得凭空给生产承诺。
2. 作业、行和草稿的精确表结构及HTTP字段：必须从本方案状态、分页、幂等和恢复要求推导，不能使用万能JSON替代业务列。
3. Office有界执行器的线程数、队列和超时：按应用单机基线冻结，不开放管理员任意调大。
4. 导出工作簿样式与页面布局：使用现有Element Plus和语义令牌，以正常短路径优先，不另建视觉体系。

上述工程决定一旦影响用户语义、权限、是否部分成功或引入新运行时组件，必须退回项目负责人确认。

## 7. 方案依据

- Apache POI官方组件说明确认XSSF/XWPF分别覆盖XLSX/DOCX；5.4.0起拒绝OOXML重复ZIP条目，当前稳定版5.5.1。
- Apache POI安全指南明确指出解析不可信文件时库本身不能完全隔离影响，因此本方案要求应用层硬限制和有界执行，不声称沙箱。
- Apache Commons CSV官方稳定版1.14.1提供固定格式与按表头读取能力；不采用SNAPSHOT。
- OWASP文件上传指南要求扩展名白名单、真实类型校验、系统文件名、非Web根目录、权限、容量限制、CSRF和可用时的扫描/CDR；本项目无扫描服务，按已确认边界明确降级声明而非伪造通过。
