# 0.2 仓储 Agent 功能设计

> 状态：已确认（第一版基线）
> 版本：0.2
> 日期：2026-08-20
> 上级索引：[`V0_2_WAREHOUSE_AGENT_DESIGN_INDEX.md`](V0_2_WAREHOUSE_AGENT_DESIGN_INDEX.md)
> 维度：只定义产品功能、状态、交互和错误语义

## 1. 核心对象与结果

| 对象 | 产品含义 |
| --- | --- |
| Conversation | 用户拥有的长期对话与History容器 |
| Memory Segment | Conversation内一次连续短期上下文段 |
| Conversation Task | 用户跨多轮逐步说清楚的一个查询目标 |
| Run | 服务端接受的一次用户提交 |
| Model Iteration | 同一Run因工具结果继续进行的一轮模型理解 |
| Attempt | 同一外部步骤因瞬时故障产生的一次技术尝试 |

技术状态与业务结果分开：

```text
Run status:
SUCCESS | FAILED | CANCELLED | PARTIAL

Business outcome:
ANSWERED | CLARIFICATION | NO_DATA | NO_EVIDENCE
OUT_OF_SCOPE | POLICY_REFUSAL | DEGRADED
```

## 2. FUN-00：Agent启用与运行前校验

### 目标

保持模板默认零配置可用，并在显式开启Agent后，用唯一确定路径校验DeepSeek、Qwen Embedding和知识PostgreSQL。

### 行为合同

- 默认关闭时不创建AI客户端、知识DataSource、向量存储、对话Controller和前端入口；
- 提供不触发模型或知识Bean装配的受保护能力发现接口，只返回`enabled`和已登记交互能力；前端据此隐藏或展示Agent入口；
- 关闭时不校验AI Key，不执行知识迁移，不产生AI数据；
- 开启时必须一次性校验聊天Key、Embedding Key、模型名、1024维和知识数据源解析结果；
- 独立知识配置优先；未配置且业务主库为PostgreSQL时复用业务DataSource；其他情况启动失败；
- 配置、迁移、扩展或维度不匹配属于启动失败，不转用其他模型、数据库或内存实现；
- 独立知识数据源、Embedding或检索链路的运行期故障属于可见降级，不影响人工仓储页面；复用业务PostgreSQL时若数据库整体不可用，按业务主库故障处理，不能伪装成仅Knowledge降级。

### 非目标

不做运行时开关、后台修改Key、Provider自动切换、配置中心和动态模型发现。

### 对应场景

SCN-CFG-01～04。

## 3. FUN-01：Conversation与History

### 目标

在DOCKED、COMPACT和DRAWER三种界面中保持同一Conversation，使用户能够查看本人历史、继续当前短期上下文或开始新话题。

### 行为合同

- 展开、折叠和切换主页面不创建新Conversation；
- History仅本人可见，默认保留180天；
- Memory按已确认的空闲TTL分段，过期History仍可见但不自动回灌；
- 部门或权限范围变化时下一轮创建新Segment；
- FAILED、CANCELLED和PARTIAL助手消息不作为完整回答进入后续Memory；
- 用户明确开始新话题时结束当前未完成Task，但不删除History。

### 非目标

不做跨用户共享、长期偏好、自动摘要、个人记忆向量化和分支会话。

### 对应场景

SCN-RP-04、SCN-RP-07、SCN-C-02～06、SCN-E-05。

## 4. FUN-02：Conversation Task与澄清

### 目标

支持用户通过三轮甚至更多轮逐步补全、纠正和确认一个仓储查询，而不是每轮让模型重新猜测整段History。

### Task状态

```text
COLLECTING | READY | COMPLETED | CANCELLED | REPLACED | EXPIRED
```

一个Memory Segment最多一个活动Task。Task只保存：

- 查询目标类型；
- 已确认的受权物品、仓库、库位引用；
- 已校验的时间范围和普通条件；
- 当前缺失字段；
- 有界候选集合及revision；
- 澄清轮次、状态、更新时间和范围指纹。

### 澄清策略

1. 第一次缺失时只问一个最关键条件；
2. 有有限候选时展示候选选择卡；
3. 仍不能确认时给示例、打开列表或开始新话题；
4. 用户纠正后Task revision增加，与新条件冲突的候选和结果失效；
5. TTL到期、范围变化、取消或明确新目标结束当前Task。

### clarification-choice

候选选择卡固定包含：

```text
clarificationId
question
selectionMode = SINGLE
options[] = optionToken + title + distinguishingFields
allowFreeText
expiresAt
```

点击选项只是一次新的受控提交，不能直接在浏览器推进Task。过期、revision不匹配或权限变化时必须重新澄清。

### 非目标

不做通用工作流、嵌套任务、跨天恢复、任务队列和任意自定义状态。

### 对应场景

SCN-RP-01～07、SCN-I-03/04。

## 5. FUN-03：仓储实时查询

### 目标

提供四类已确认只读能力：物品定位、按物品查库存、按库位查内容、查近期库存移动。

### 行为合同

- 对象唯一且条件完整时返回受信业务结果；
- 多候选时进入FUN-02，不静默选择；
- 实时库存只来自仓储公开API；
- 每次查询重新使用当前身份和部门范围；
- 无数据、不存在、无权限、参数错误和系统故障使用不同结果；
- 请求过宽时要求缩小条件，不自动遍历全部分页。

### Tool结果语义

```text
RESOLVED | AMBIGUOUS | NO_DATA | NOT_FOUND
DENIED | INVALID | UNAVAILABLE
```

DENIED不能泄露目标对象存在性；UNAVAILABLE不能伪装成空结果。

### 对应场景

SCN-N-01～03、SCN-RP-01～06、SCN-AU-02/03/05/06、SCN-D-01/02。

## 6. FUN-04：业务结果卡、复制与打开页面

### 目标

将受信仓储结果转换为可读、可复制、可打开人工页面的固定卡片。

### 卡片

- item-location；
- stock-summary；
- location-contents；
- movement-list；
- clarification-choice属于对话交互卡，不属于库存事实卡。

### 共同字段

库存类卡片至少表达：查询时间、物品与单位、仓库/库位范围、结果是否截断。复制整卡时保留这些上下文。

### 动作

- copy只复制已渲染受信字段；
- route只使用登记routeKey和窄参数；
- 打开页面后重新加载、鉴权和校验；
- 卡片快照不能作为人工提交依据。

### 对应场景

SCN-N-01～03、SCN-D-01、SCN-S-06、SCN-B-01/02。

## 7. FUN-05：异常输入与安全响应

### 目标

在不误伤正常口语和业务编码的前提下，处理乱码、冒充、注入、参数侵入、枚举、秘密和情绪化输入。

### 前置拒绝

空白、明确超长、非法控制字符、不可接受编码和已知技术秘密不进入模型与业务工具。用户得到具体但不泄露内部实现的提示。

### 语义澄清

可打印乱码、疑似编码损坏、矛盾条件和无法唯一理解的输入进入CLARIFICATION，不调用最终业务查询。

### 身份声明

“我是老板/管理员”“老板让我查”等只是文本。实际能力只按当前登录账号计算；用户询问自身能力时只展示“本部门/全部门”等产品化范围。

### 注入与工具侵入

- 合法业务意图可以可靠分离时，只处理合法部分；
- 无法分离时要求用户重新用普通语言描述；
- 不泄露系统提示、隐藏推理和密钥；
- 不执行用户或模型伪造的工具、SQL、URL和身份参数；
- RAG、业务字段和History都不能取得指令权。

### 情绪和离题

辱骂中有合法仓储请求时继续处理；纯辱骂不反击、不说教；离题时简短说明能力边界。首版不建设情绪画像或内容审核平台。

### 对应场景

SCN-I-*、SCN-AU-*、SCN-S-*、SCN-O-*、SCN-B-02。

## 8. FUN-06：Knowledge与混合查询

### 目标

回答仓储制度和编码规则，并在混合问题中把知识依据与实时业务事实分开。

### 行为合同

- 首版知识源只使用仓库内登记的合成Markdown样本，至少覆盖仓储操作、物品编码、仓库与库位编码；
- 样本必须带稳定文档编码、版本、生效状态、合成标识和内容哈希；
- 由受保护的固定样本导入动作读取登记资源，不接受上传文件、任意路径和任意正文；
- 相同内容、模型和维度重复导入必须幂等；内容或Embedding契约变化形成新索引事实；
- 知识回答必须带有效文档、版本和片段引用；
- 零命中返回NO_EVIDENCE，不用模型常识补充；
- 运行期不可用时发出可见降级；
- 实时库存成功、知识失败时可以形成PARTIAL或DEGRADED；
- 检索片段只作为数据，不能改变工具、权限、卡片和路由。

### 对应场景

SCN-K-01～03、SCN-N-04、SCN-S-05、SCN-E-01/03。

### 非目标

不做知识管理页面、用户上传、在线编辑、审批发布、OCR、PDF/Word解析、自动抓取和定时增量同步。

## 9. FUN-07：Run、流式、重复、取消与重试

### 目标

保证一次提交只有一个Run和唯一终态，防止双击、并行回答、自动重放和迟到事件污染History。

### 行为合同

- 同一Conversation同时只允许一个活动Run；
- 输入框运行中可继续编辑，新消息采用明确的“中断并发送”；
- 相同clientRequestId不重复执行模型和Tool；
- 用户主动重试创建新Run并关联retryOfRunId；
- 折叠和导航不取消，明确停止和网络断开分别记录；
- 无可见输出前用户取消为CANCELLED；已有文字、引用或卡片后中止为PARTIAL；
- 迟到事件不能覆盖新Run或已形成的终态；
- Attempt只用于明确瞬时故障，不等于模型工具迭代或用户重试；
- 每个外部模型或Embedding步骤首次调用失败后最多自动重试2次，即该步骤最多3个Attempt；Spring AI或供应商SDK的隐藏重试必须关闭，由项目层统一计数和观测；
- 只有超时、限流、连接瞬断和明确的供应商5xx可以自动重试；配置、认证、参数、权限、Schema、业务拒绝、无数据和无证据不得重试；
- 已发送任何文字、引用或卡片，或者已经执行Tool后，不得透明重跑整个Run；后续模型总结失败时可以复用本Run已缓存的Tool结果，但不得再次执行Tool；
- Tool结果触发的下一次模型推理属于新的Model Iteration，不占用前一Iteration的Attempt次数，仍受单Run模型与Tool总预算约束。

### 对应场景

SCN-C-*、SCN-E-02/05/06。

## 10. FUN-08：用户结果、异常表达与效果反馈

### 用户结果

| 情况 | 必须表达 |
| --- | --- |
| 成功空结果 | 没有找到符合条件的数据 |
| 对象不存在 | 没有找到指定对象 |
| 描述不清 | 需要补充或选择候选 |
| 无知识证据 | 没有找到可引用依据 |
| 无权限 | 当前账号不能查询该范围，不泄露对象存在性 |
| 系统故障 | 说明哪个能力暂不可用及可行下一步 |
| 部分完成 | 保留已验证内容并标出未完成部分 |
| 写操作请求 | 明确未执行，只提供人工入口 |

### 效果反馈

- 完整助手消息可以赞踩并选择原因；
- FAILED、CANCELLED和PARTIAL不作为完整回答评价；
- 对话效果必须同时看Task是否完成、澄清轮次和最终业务结果，不能只看Run成功率。

### 对应场景

SCN-RP-*、SCN-B-*、SCN-E-*、SCN-O-*。

## 11. FUN-09：AI观测与离线评测

### 目标

让管理员定位一次回答经过了哪些模型、检索、Tool、流式和History步骤，并用固定样本持续检查回复效果。

### 行为合同

- 运行详情按Task、Run、Step、Model Iteration和Attempt展示有序链路；
- 技术成功、业务结果、降级和用户反馈分别记录，不能只统计HTTP成功率；
- 管理端至少提供概览、运行列表、运行时间线和评测结果；
- 固定评测记录数据集、模型、配置、知识和规则版本；
- 部门越权、写Tool、错误业务事实和虚假引用使用确定性断言；LLM评分只补充相关性和有据性；
- 观测默认只保存标识、状态、耗时、Token、数量、版本和错误码，不复制History、知识与Tool正文。

### 对应场景

SCN-OB-01～03、SCN-E-02～06。

## 12. FUN-10：可裁剪业务适配

### 目标

证明仓储是第一个业务适配而不是Agent核心的一部分，同时不提前建设动态插件平台。

### 行为合同

- 仓储Tool、仓储卡片和仓储routeKey只存在于仓储适配模块；
- 移除仓储适配后，Agent、Knowledge和Observability不得出现仓储类型、包名、表名或权限码依赖；
- 适配采用编译期模块装配，工具名或资产标识冲突时启动失败；
- 第二个真实业务消费者出现前，只声明边界可裁剪，不声明跨业务复用已被证明。

### 对应场景

SCN-RU-01。

## 13. 功能配置边界

可以配置：输入上限、Memory空闲TTL、模型超时、单Run模型/Tool/结果/Token/墙钟硬上限。瞬时故障自动重试上限在0.2固定为2次，不开放给普通用户或由模型动态放大。

不可任意配置：权限规则、工具白名单、澄清语义、Task状态、业务结果、卡片字段、routeKey和安全不变量。

DeepSeek首版固定使用`deepseek-v4-flash`。锁定的Spring AI 2.0.0适配器不能显式关闭V4默认思考模式，因此`reasoning_content`只允许在同一Run的模型工具续轮中临时回传，禁止展示、写入History或Observability，也不作为运行时用户参数。SLICE-00 Gate B已通过真实流式Tool续轮验收；后续分片复用该基线，不得在没有回归证据时重开Provider协议改造，也不得升级快照依赖或增加自建Provider适配层。

模型与Tool总预算数值必须通过真实场景PoC采样后确认；任务复杂度不能由模型自由声明后自动扩大权限或预算。

## 14. 功能验收边界

- FUN-00通过默认关闭、缺配置、两种知识DataSource解析和启动失败语义验收；
- FUN-01/02通过三轮黄金脚本、纠正、TTL和范围变化验收；
- FUN-03/04通过真实Warehouse API、部门隔离、卡片时点和人工页面重验收；
- FUN-05通过乱码、冒充、直接/间接注入、参数侵入、枚举和秘密样本验收；
- FUN-06通过合成样本幂等导入、真实Embedding/pgvector、版本引用、零命中和运行期不可用验收；
- FUN-07/08通过重复、并发、取消、PARTIAL、History和效果反馈验收；
- FUN-09通过完整时间线、异常定位、内容不复制和固定评测验收；
- FUN-10通过移除仓储适配后的依赖扫描和构建验收。
