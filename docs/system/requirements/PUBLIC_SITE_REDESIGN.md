# 需求：公开主页改版（布局 + 子内容）

> 规模：大需求
> 状态：已确认（2026-08-04）
> 来源：[需求索引中的轻量需求漏斗](../../../requirements/README.md#8-需求漏斗只确认影响实现的差值)
> 实施状态：已完成；当前行为与装配边界以 `module-site` 能力契约、OpenAPI 和自动化测试为准

## 一句话意图

公开主页从"简单单块"升级为有完整布局、可编辑子内容（区块）、铺满浏览器的正式展示页。

## 功能（要做什么）

- ① 2 种代码定义固定布局（布局为代码枚举，管理端可选，可后续增加）；
- ② 区块（子内容）管理端可增删改：标题、内容、配图（可空）、排序；
- ③ 区块类型第一批 3-4 种：关于我们 / 服务产品 / 新闻标签 / 联系方式；
- ④ 公开页按所选布局 + 区块渲染，视觉铺满浏览器，延续 Minimal Tech + GRAPHITE/AZURE 双配色；
- ⑤ 草稿/发布隔离沿用现有机制：编辑草稿不影响线上，发布整体生效。

## 主流程

1. 管理端：选择布局 + 编辑区块（增删改/排序/配图）→ 保存草稿；
2. 预览草稿（按布局+区块渲染）；
3. 发布 → 草稿布局与区块整体复制为发布快照；
4. 公开页按发布快照的布局 + 区块渲染。

## 异常流程

- 区块配图文件不存在 → 保存草稿时明确拒绝；
- 发布失败 → 旧公开快照保持有效（无半发布）；
- 空区块集 → 公开页显示兜底（不空白报错）；
- 管理端未选布局 → 使用默认布局。

## 验收标准

- 公开页按所选布局渲染且铺满浏览器；
- 区块增删改/排序/配图在管理端可用，发布后公开页生效；
- 修改草稿不影响已发布页面；撤回后公开页不可见；
- 双配色在改版后仍生效。

## 非目标（明确不做）

- 不做拖拽自定义布局、不做区块类型插件化、不做新闻单独管理（区块内文本即可）、不做历史版本。

## 实体关系认识（涉表，实现依据）

```text
主页（draft / publication，单例，已有）
  ├─ layout_code（新字段）：代码枚举 GRID_SPLIT / BANNER_SPLIT（2 种）
  └─ 区块 Section（新实体）：主页 1—N 区块
       ├─ section_type：ABOUT / SERVICE / NEWS / CONTACT
       ├─ title / content / hero_file_id(可空) / sort_order
       └─ 配图 N—1 file_asset（只存标识，不建外键）
```

## 表结构认识（实体 → 表，实现时新增变更集）

- `site_homepage_draft` / `site_homepage_publication`：**加列** `layout_code`（VARCHAR）；
- 新增 `site_homepage_draft_section`（草稿区块，id、section_type、title、content、hero_file_id 可空、sort_order）；
- 新增 `site_homepage_publication_section`（发布快照区块，同结构）；
- 发布时：事务内复制 主页快照 + 全部草稿区块 → 发布区块（与现有快照复制语义一致）。
