## 1. 核心目标

在不启动服务、不写数据库、不运行测试的前提下，判断 V01-12 能否在当前仓库形成“干净来源 → 本地完整质量 → 开发脚本生命周期 → 真实 Chromium → 远端 GitHub Actions”的可复现发布证据，并把需要项目负责人授权的动作压缩到最小集合。

本任务只是预检，不代表 V01-12 正式验证通过。

## 2. 必须完成

- 只读核对当前分支、工作区状态、远端地址和是否具备建立干净验证副本的前置条件；
- 核对 JDK 25、Maven Wrapper、Node 24、锁文件、Playwright Chromium 缓存、端口和现行 `quality.sh`/`dev.sh` 入口；
- 给出 V01-12 的唯一串行执行顺序、每步副作用、预计证据、停止条件和失败后的责任角色；
- 明确哪些步骤必须等当前共享改动提交后才能证明“干净环境”，不得把当前脏工作区运行冒充干净环境；
- 明确远端 GitHub Actions 首次运行是否需要提交和推送，以及本对话当前是否已获授权；
