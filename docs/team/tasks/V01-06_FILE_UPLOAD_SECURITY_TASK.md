## 1. 核心目标

把文件上传从“相信客户端 MIME 与扩展名后直接落盘”收敛为真实图片识别、资源限制、完整解码、单帧验证和失败清理闭环，使伪装、损坏和资源消耗型图片被明确拒绝，任何失败都不留下临时文件、最终文件或元数据。

## 2. 范围与非目标

### 必须完成

- JPEG、PNG 使用 JDK ImageIO，WebP 使用 TwelveMonkeys ImageIO 3.14.0；
- 保留 10MB 字节上限，新增宽高单边不超过 8192、总像素不超过 40,000,000、只允许单帧；
- 实际格式、最终扩展名和响应 Content-Type 从解码器识别结果派生；客户端文件名和 MIME 只作输入，不作最终事实；
- 按“受控临时文件 → 验证 → 随机最终文件名 → 元数据登记”的顺序实现；任一后续失败清理临时文件和已经产生的最终文件；
- 补齐不访问数据库的自动化测试，并同步 module-file 能力包当前状态。

### 明确不做

- 不统一重编码，不承诺剥离 Exif、ICC、XMP、尾随数据或所有 polyglot 风险；
- 不引入对象存储、病毒扫描、异步图片处理、缩略图或新的公开接口；
- 不改 Session、安全配置、IAM、前端、数据库结构、迁移和 0.1 任务总表。
