## 1. 核心目标

建立一套最低必要、可以重复执行的前端测试主路径：Vitest + Vue Test Utils + jsdom 负责高风险组件与路由组合行为，Playwright 负责真实前后端业务闭环；两层职责不重复，失败必须可见。

本任务按权限边界分为两个可审查状态：

1. **当前实现闭环**：依赖、配置、组件/组合测试和真实 Playwright 用例定义完成，并在无数据库条件下完成组件测试、类型检查、构建和 E2E 测试发现验证；
2. **真实 E2E 验证**：项目负责人明确授权目标后，由运维工程师准备隔离 SQLite、隔离上传目录并启动真实前后端，执行 Chromium 闭环。2026-08-11 已完成并通过。

### 5.1 草稿异步回填缺陷的授权决定（2026-08-11）

全量 Vitest 早期反馈发现：`SiteManagePage.vue` 对 `draftQuery.data` 使用带 `immediate: true` 的 watcher，首次数据仍为 `undefined` 时便将 `hydrated` 标记为 `true`；后续真实草稿异步到达后不再执行 `loadDraft()`，导致已有草稿无法回填表单。

总设计师独立核对代码与失败用例后确认根因成立。项目负责人于 2026-08-11 明确授权一次单文件最小生产修复，边界如下：

1. 只允许在真实草稿存在并完成 `loadDraft()` 后设置 `hydrated = true`；
2. 禁止改变接口、字段、校验、查询 key、保存/发布/撤回逻辑、样式或其他业务文件；
3. 必须保留并通过能够复现该缺陷的回归测试，禁止改成空草稿场景、删除断言或增加无条件等待；
4. 修复后重新执行全部 Vitest、Playwright `--list`、类型检查、构建和 `git diff --check`；
5. 实施报告必须记录首次失败、生产根因、授权边界、最小补丁及复验结果。

该授权只关闭 V01-09 当前测试发现的直接阻塞，不构成一般性业务代码修改权限。

### 5.2 空主图 ID 请求缺陷的授权决定（2026-08-11）

真实 E2E 结束后的后端日志显示：编辑页尚无主图时，预览组件仍生成 `/api/files/` 请求并触发 `NoResourceFoundException`。总设计师核对 `SiteManagePage` 初始状态与 `HomepageShowcase` 渲染链后，授权以下最小修复：

1. 仅在 `content.heroFileId` 非空时渲染主图容器和图片；
2. 不修改 API helper、后端异常处理、DTO、样式或其他页面行为；
3. 必须新增回归测试，证明无草稿、无主图时不存在主图元素和 `/api/files/` 空地址；
4. 修复后重新执行目标测试、全部 Vitest、类型检查、构建和 `git diff --check`。

## 8. 实现约束

- 组件测试断言用户可观察行为、路由结果、API 调用边界和缓存失效，不断言 Vue 内部实现细节；
- 每个用例必须能说明删除对应生产行为后会如何失败；禁止只断言组件能够挂载；
- Element Plus 全量挂载若造成无关噪声，只允许建立一个最小统一测试初始化，不得创建通用 Mock 框架；
- E2E 不得使用 `page.route()`、固定成功响应或静态页面替代主业务接口；
- E2E 凭据只从环境变量读取，缺失时必须明确失败或仅在 `--list` 阶段不执行，不得写入仓库；
- 上传使用仓库内许可证清楚、尺寸受控的固定图片样本；如新增二进制样本，必须记录来源和校验值；
- 当前环境不得通过运行应用验证页面效果；这不是降低 E2E 标准，而是把真实运行责任显式留给外部验证。
