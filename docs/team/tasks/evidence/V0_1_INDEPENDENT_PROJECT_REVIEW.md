## 2. 原目标、实际成果与差距

已确认的 0.1 范围要求以一个公开主页业务闭环，验证 AI 对数据库、后端、API、前端、权限、测试和文档的受约束装配，并提供零数据库启动和统一质量入口。发布矩阵中 11 项需求、12 项完成标准已形成对应的工程证据。

项目愿景同时已确认模板应支持派生独立系统和系统内模块组合，面向独立开发者保持低使用负担。实际产出证明了参考应用可运行、可验证和具备关键安全质量，但没有证明：项目身份可控替换、参考 `site` 可移除、通用模块可按需组合，或能力包可由第二个模块重复使用。

最有价值的实际产出是统一质量入口、Session/CSRF、文件真实内容校验和失败清理、权限与发布快照隔离、真实浏览器主链、模块公开 API 与能力包基础结构。

## 3. 最严重偏离与当前风险

最严重偏离是成功标准的目标替换：参考主页的安全、完整和发布验收实际成为版本中心，模板派生、改名、裁剪和复用未成为完成标准。

静态事实表明参考业务仍污染模板装配边界：`module-file` 直接使用 `site:homepage:edit` 权限并将匿名公开读取交给 `module-site`；`app-server`、Liquibase 主链、前端路由与导航、OpenAPI 断言和质量测试均直接依赖 `site`。因此不能称 `site` 已是低成本可裁剪模块。

当前风险为中等：参考应用可交付，但继续通过增加参考业务来证明模板，会继续扩大耦合与维护面。构建工具链依赖审计中的 P1 项是维护事项，不构成当前工程阻断。

## 4. 生产方法、根因与责任

生产方法未通过的主因不是安全、测试或 CI 本身，而是没有按风险及时收敛：范围有限的封版被拆成高合规、多角色、多轮验收与多份长期证据链；定位器、命令目录和临时脚本等可恢复问题被升级为流程事件；真实浏览器主链探路偏晚；文档治理量超过产品价值所需。

总设计师对方向和成本负主要责任：没有在封版前把模板派生、裁剪和复用转化为完成标准，也没有在参考应用已充分证明后停止追加流程。研发、运维、网络和环境问题是成本放大器，不是根因；更深的结构性问题是把“证据齐全”误当作“模板价值已证明”。

已落地的 L0/L1/L2、成本止损和单一最终证据规则方向正确，但尚未经真实版本交付证明能降低任务数、验证轮次与投入，故不能因规则文本已存在而判定生产方法已经通过。

## 5. 下一阶段建议

### 必须处理

1. 只开展一个 L1、最多两轮验证的模板派生闭环：项目身份替换清单、`site` 裁剪、无 `site` 的后端/前端构建和无数据库门禁、第二个极小业务模块装配。
2. 先消除通用模块中的 `site` 专属权限和公开读取耦合，再提供可验证的裁剪步骤。
3. 将上述模板消费者路径写入下一版本完成条件，不能用参考业务功能或文档数量替代。

### 建议处理

- 保留统一质量入口、关键安全回归和一次最终发布验证。
- 以派生所需步骤、触及文件、失败轮次和人工判断负担作为成本指标。

### 明确停止投入

- 不继续扩展公开主页业务；
- 不新增角色、任务矩阵、实施报告或重复验收链；
- 不将未验证的“模块可删、可组合、可升级”表述为事实；
- 不为裁剪问题引入插件框架、动态模块系统或额外运行时抽象。
