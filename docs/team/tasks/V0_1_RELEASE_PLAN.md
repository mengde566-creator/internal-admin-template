## 1. 核心目标

在不增加 0.1 业务范围的前提下，完成契约、安全、测试、质量门禁、能力包、文档与验收证据收口，使 0.1 从功能候选版进入可以重复验证和正式验收的版本状态。

0.1 封版期间禁止加入 Agent 运行时、知识库正式实现、微服务、OAuth2/OIDC、对象存储、通用参数平台、工作流、多租户和低代码能力。

## 2. 使用与维护规则

1. 本文件是 0.1 封版任务状态的唯一事实源，不复制需求、架构和接口正文；任务实施必须回到对应权威文件。
2. 只有总设计师 / 总架构师可以更新本文件中的任务状态、依赖关系、验收结论和角色分配。
3. 执行角色不得自行把任务标记为完成；必须在所属对话提交改动范围、实际验证、未执行项和风险，由总设计师 / 总架构师复核后更新状态。
4. 每次派发必须包含任务 ID、目标、必读材料、允许修改范围、禁止事项、完成标准、验证要求和交付格式。
5. 多个角色共享同一工作目录。并行任务必须划分互不重叠的源文件范围；构建产物同样共享，并行期间禁止执行 `clean`，发现重叠时后启动任务必须暂停并通过跨对话消息报告总设计师。
6. 任务状态只使用：`待开始`、`进行中`、`待审核`、`阻塞`、`完成`。
7. 新增角色、扩大角色职责或改变已确认产品范围，必须先由项目负责人确认，不得通过任务分配变相生效。
8. 所有角色继续遵守数据库严格只读边界，不执行迁移、测试库写入、数据修改或数据库重置。需要数据库写入的最终验证由项目负责人在外部允许环境触发，角色只读取并复核结果。
9. 执行角色收到任务、发现阻塞和完成自我复盘后，必须使用 Codex 跨对话消息能力向总设计师对话发送“接收”“阻塞”或“申请验收”回执；不得依赖项目负责人手工搬运进度。

## 5. 首批派发边界

### V01-03：信息分析专员

- 目标：为 V01-04 提供可核验的技术证据，不直接选择项目方案。
- 必须研究：
  1. Spring Boot 4 项目生成 OpenAPI 及前端 TypeScript 类型的成熟方式；
  2. Vue 3 + Vite 的组件测试和浏览器 E2E 最小组合；
  3. Spring Session Cookie 安全属性的官方配置与可验证方式；
  4. JPEG、PNG、WebP 真实文件内容识别与安全解码方案；
  5. 本地与 CI 复用同一质量入口的成熟实践。
- 交付路径：`docs/team/tasks/evidence/V01-03_TECHNICAL_RESEARCH.md`。
- 禁止：修改本任务总表、需求、架构、依赖、业务代码、测试和数据库相关文件；不得安装依赖或执行数据库写入。
