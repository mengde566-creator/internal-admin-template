## 1. 核心目标

补齐 IAM P0 集成测试，并关闭真实验证发现的初始化管理员删除保护缺陷：保护对象必须按唯一初始化账号识别，禁止继续假设数据库 ID 固定为 `1`。

## 2. 范围与非目标

### 必须完成

- 使用真实创建角色、创建用户、登录和受保护 API，证明无权限用户访问 IAM 管理、发布或上传接口返回 403；禁止用 `user()` 注入 authority 冒充持久化权限装配；
- 删除初始化管理员和当前登录账号均被拒绝，并断言精确业务原因；
- 用户软删除后，正常查询与登录均不可见，同时存在一条 `USER_DELETE / SUCCESS` 审计；
- 无引用角色删除后，角色、角色权限关联均不存在，并存在一条 `ROLE_DELETE / SUCCESS` 审计；
- 保留既有角色引用保护和软删除引用过滤测试，不重复实现同义测试。
- 修复 `UserService` 对初始化管理员的固定 ID 假设，按已确认的唯一初始化账号 `admin` 判断保护对象；同步纠正能力包中的旧事实。

### 明确不做

- 不修改数据库结构、Liquibase、POM、Session/Cookie 文件、前端或 V01-08B 文件；生产代码只允许修改 `UserService` 的初始化管理员判断；
- 不扩展权限模型、恢复/回收站、失败审计或通用审计查询；
- 不创建新的测试框架、基类或通用 fixture 系统。
