# 团队角色定义与生成规范

> 状态：生效
> 版本：0.4

## 1. 建立触发

只有存在持续且当前真实需要的结果责任、现有角色无法无冲突承担、新角色能够减少责任真空或返工，并经项目负责人确认时，才建立角色。短期任务、单一技能、一次研究/验证和未来设想不构成角色；一个执行者能闭环时禁止为分工创建角色。

## 2. 权限与责任

- 角色应拥有完成结果责任的最小权限，不能要求其负责却禁止全部必要动作；
- 头衔不扩大产品、架构、数据库、外部资源或不可逆操作权限；
- 不同角色不得同时拥有同一事项的最终裁决权；
- 共用 L0/L1/L2、等待、数据库、回复、跨对话和自审规则只引用根 `AGENTS.md` 与 `VERSION_DELIVERY_PROTOCOL.md`。

## 3. 不成为事实源

角色文档只定义定位、结果责任、权限和边界，不重新解释愿景、需求、架构、代码或运行状态。履职时必须读取原始权威材料；角色作者摘要、审议意见和历史对话不能代替原文。

## 4. 创建、变更与停用

- 创建：提出责任缺口 → 核对现有角色 → 起草一份角色文档 → 项目负责人确认 → 登记目录；
- 变更：职责、决策权或长期边界变化必须说明对现有角色的影响并由负责人确认；措辞调整不得暗中扩权；
- 停用：责任消失、被合并、长期不再需要或角色持续制造重复成本时，由负责人确认并更新目录。历史由 Git 保留。

## 5. 精简模板

```markdown
# <角色名称>
> 角色 ID / 状态 / 版本 / 一句话定位
## 1. 结果责任
## 2. 核心职责
## 3. 决策权限（可独立 / 必须确认 / 禁止越权）
## 4. 特有升级与协作
## 5. 共用执行规则（只引用 AGENTS 与交付协议）
## 6. 失职、纠正与停用
```

只保留角色独有内容，不为形式完整增加流程、回执、交付表或自审清单。
