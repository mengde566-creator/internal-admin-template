# 模板派生与可选模块裁剪指南

本指南用于从模板派生一个可选业务模块或裁剪现有模块。它只描述复用步骤，不承诺一键卸载，也不复制任何具体业务模块的装配清单。

## 1. 读取唯一契约

先读取目标模块的 `capability/CAPABILITY.md`，以及根规范、需求、模块架构和认证架构。把其中的源装配点、需重新生成的产物和历史证据边界分开；历史任务和验收记录不能当作当前代码清单。

## 2. 替换身份

为派生模块确定新的模块名、Java 包、前端目录、路由、权限编码、数据库对象、审计动作和 OpenAPI 标签。只保留已有真实调用方；权限写入中央目录，跨模块调用只依赖公开 `api/` 契约，不新增权限 SPI、插件注册表或双权限兼容。

## 3. 裁剪装配面

按契约逐项处理 Maven reactor、应用依赖、组件与 Mapper 扫描、Liquibase 聚合、权限目录、审计调用、Controller/OpenAPI、前端路由与导航、package/Vitest/Playwright/E2E 和统一质量入口。移除源码及其直接引用，保留历史证据；不得修改已发布变更集或自动改写既有角色数据。公开 Controller 必须符合 `/api/public/**` 的匿名命名空间规则并保留发布可见性校验。

## 4. 验证与生成

先执行静态残留扫描和模块编译，再按统一质量入口执行无数据库检查；获得项目负责人针对隔离目标的明确授权后，才执行数据库/启动验证。OpenAPI 与前端类型必须由现有生成入口从真实代码重新产生并执行漂移检查，禁止手工编辑生成物。最后检查前端类型、单元测试、Playwright 用例清单以及需要的真实链路。

## 5. 升级记录

记录被移除或替换的模块、权限行为、生成物命令和未执行验证。权限语义变化只登记管理员需要在角色管理中手工补充或移除的权限；不创建数据库迁移、双权限兼容或新的升级框架。把当前结果写入本次唯一任务记录，历史证据保持原样。
