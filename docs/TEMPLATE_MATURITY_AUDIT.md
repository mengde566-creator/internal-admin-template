# 0.1 模板成熟度轻量审计

> 审计日期：2026-08-12
>
> 审计级别：L1（轻量）
>
> 审计对象：0.1 模板派生能力，不重复验收参考应用业务功能

## 1. 核心结论

**0.1 已是可运行、可验证的参考应用，但还不是可稳定派生的成熟模板。**

四项模板门禁中：1 项通过、1 项部分通过、2 项未通过。当前最主要的问题不是功能缺失，而是项目身份和参考业务仍与模板骨架耦合，使用者尚不能低成本完成“复制、改名、裁剪、扩展”。

| 模板门禁 | 结论 | 一句话判断 |
| --- | --- | --- |
| 干净环境启动 | 通过 | 固定 SHA 已完成干净副本、依赖安装、迁移、启动、E2E、停止和远端 CI 闭环 |
| 项目身份替换 | 未通过 | 名称、包名和展示身份分散在约 120 个文件中，没有受控替换清单或验证路径 |
| 移除参考 `site` 业务 | 未通过 | `site` 同时耦合构建、应用依赖、迁移、路由、导航、契约和质量门禁 |
| 用能力包新增第二模块 | 部分通过 | 模板和多个能力包实例已存在，但缺少一次可追溯的端到端派生证明 |

## 2. 门禁依据

### 2.1 干净环境启动：通过

`V01-12_FULL_VALIDATION_REPORT.md` 已对固定 SHA `90d4d313b3483f07237a6e0cf342953d980f20f5` 证明：

- 干净 worktree 与锁定依赖安装成功；
- `quality.sh --database` 通过，Liquibase `Run=16 / Total=16`；
- `dev.sh start/status/stop` 生命周期通过；
- Chromium 真实链路 3/3 通过；
- GitHub Actions 对同一 SHA 运行成功。

该 SHA 之后的提交没有修改生产 Java、Vue、迁移或运行脚本，因此本次轻量审计复用已有证据，不重复消耗完整验证成本。

### 2.2 项目身份替换：未通过

静态检索发现 `internal-admin-template`、`com.internaladmin`、`Internal Admin`、`Admin Workspace` 分布在约 120 个非构建文件中，涉及：

- Maven 坐标与模块父级；
- Java 包名和应用配置；
- 前端包名、页面标题与界面文案；
- 脚本、文档及生成链。

仓库当前没有说明哪些身份必须替换、哪些内部标识可以保留，也没有替换后的编译和启动验证清单。因此“能手工改名”不等于“模板已具备可控派生能力”。

### 2.3 移除参考 `site` 业务：未通过

`module-site` 目前至少直接进入以下公共装配点：

- `backend/pom.xml` 的 Maven reactor；
- `backend/apps/app-server/pom.xml` 的应用依赖；
- `db/changelog-master.xml` 的迁移主链；
- 前端路由和系统侧边栏；
- OpenAPI 契约断言、`SiteFlowTest`、质量脚本和公开站点冒烟脚本。

仓库没有模块注册清单、裁剪说明或“无 site 构建”验证。当前移除它需要跨多个公共文件手工手术，容易留下编译、迁移或测试残留，不符合模板应有的低成本裁剪目标。

### 2.4 用能力包新增第二模块：部分通过

`backend/modules/_capability-template` 已提供 `AI_PROMPT.md`、`CONTRACT.md`、`TEST.md`，IAM、文件、审计和站点模块也都有对应能力包。这证明结构设计已经存在。

但现有证据没有完整记录一次“复制模板 → 定义契约 → 实现模块 → 接入应用和前端 → 通过门禁”的独立派生过程。能力包目前更像已建立的规范，还没有被一次低成本复用实验充分证明。

## 3. 成熟度判定

当前定位应明确为：

> **可运行的内部管理参考模板（reference template），尚未达到可直接派生的通用模板。**

在改名与裁剪门禁通过前，不应继续用新增参考业务功能来证明模板成熟度。参考业务越多，反而可能扩大与骨架的耦合面积。

## 4. 最低成本补齐顺序

只建议开展一个“模板派生闭环”任务，按以下顺序执行：

1. 建立项目身份替换清单，区分必须替换的产品身份与允许保留的内部技术标识；
2. 提供 `site` 裁剪步骤，并实际证明无 `site` 的后端编译、前端构建和无数据库质量门禁；
3. 从能力包模板增加一个极小、无复杂业务的示例模块，证明第二次装配可重复；
4. 将前述三项合并为一份模板派生指南，不新增角色、版本任务矩阵或重复证据体系。

成本止损：该闭环按 L1 执行，最多两轮验证；同类失败第二次出现即停下来修正模板机制，不继续堆补丁。

## 5. 本次审计边界

本次只进行了文档、配置和代码引用的静态审计，并复用 V01-12 已有发布级证据；没有联网检索、启动服务、安装依赖、执行数据库、运行 Maven/npm/Playwright 或创建额外任务文档。
