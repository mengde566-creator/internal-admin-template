# <module-name> 能力包

> 通用工程规则见 [`CAPABILITY_COMMON.md`](../../../docs/development/CAPABILITY_COMMON.md)。本文件只维护本模块特有事实。

## 1. 定位与非目标

一句话说明当前解决的问题、提供的能力和明确不做的内容；链接已确认需求，并用用户语言指出核心场景，禁止复制整份需求。

## 2. 特有约束

记录只有本模块才有的业务规则、失败语义、权限、事务、数据或框架限制；不要复制根规范和通用能力规则。

## 3. 公开与跨模块契约

列出真实公开 API、跨模块 `api/` 契约、调用方责任和权限。精确 HTTP 字段指向 DTO、Controller 与生成的 OpenAPI，避免复制易漂移细节。

## 4. 数据所有权

列出本模块拥有的表、核心数据语义、DO/DTO 索引，以及跨模块只存标识、不建外键的边界。变更必须对应实际 Liquibase 文件。

## 5. 依赖与组合

列出直接依赖、被依赖方向和允许的组合方式；禁止跨模块访问内部 Mapper、DO、Service 或表。

## 6. 装配与裁剪

按实际存在的 Maven reactor/app 依赖、组件与 Mapper 扫描、Liquibase 聚合、权限/审计、Controller/OpenAPI、前端路由/导航/页面、测试/质量入口和需重新生成的产物登记；有前端时指向已确认的页面与状态契约。只列源装配点，不把历史报告、日志或构建输出当作当前代码清单。

## 7. 风险与验证入口

明确一个最先验证数据、权限、接口和页面的黄金纵切；只列测试类/脚本入口、各自必须证明的风险和当前人工缺口，不维护逐项勾选、历史通过轮次或状态矩阵。

## 8. 素材与许可证

列出实际引用的已批准素材、固定来源/版本与许可证义务；没有素材时明确说明。禁止为了填模板制造资产、依赖或报告。
