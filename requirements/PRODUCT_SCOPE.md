## 1. 产品定义

`internal-admin-template` 是用于派生企业或组织内部管理系统的完整全栈模板。它不是单纯的后端脚手架，也不是某个具体行业系统。

模板需要同时提供：

- 可运行的 Java 后端；
- 可使用的 Vue 3 管理端；
- 数据库模型、迁移和初始化机制；
- 常用内部管理能力；
- 模块裁剪、组合和扩展方式；
- 本地开发、测试和部署说明。

## 2. 要解决的问题

派生新的内部管理系统时，不应该反复建设登录、用户、组织、角色、权限、菜单、配置、审计、数据库迁移和基础管理界面。

本模板需要解决：

1. 通用能力重复开发；
2. 不同项目结构和规范不一致；
3. 新项目本地启动依赖过多；
4. 通用模块难以拆除或复用；
5. 前后端契约、权限和数据库结构容易失去同步；
6. AI 生成代码容易扩大范围、增加兜底和制造无意义抽象。

## 3. 目标使用者

### 3.1 模板维护者

维护模板能力、架构约束、模块边界和升级路径的开发者。

### 3.2 派生项目开发者

基于模板创建资产管理、项目管理、工单、客户管理等真实内部系统的开发者。

### 3.3 系统管理员

在派生系统中管理用户、组织、角色、权限、菜单、配置和审计信息的人员。

### 3.4 内部业务用户

使用派生系统完成具体业务工作的组织内部人员。模板只提供其通用账户、权限和界面基础，不预设具体业务流程。

## 4. 核心使用场景

### SCN-001：零数据库安装启动

开发者克隆项目，在没有安装 MySQL、Oracle 或 PostgreSQL 的情况下启动完整系统。系统创建本地 SQLite 文件并完成结构迁移，开发者能够访问前端页面。

### SCN-002：切换外部数据库

开发者显式配置 MySQL、Oracle 或 PostgreSQL 后，系统连接指定数据库并执行对应迁移。配置错误或连接失败时必须明确启动失败，不能回退到 SQLite。

### SCN-003：完成基础管理

系统管理员登录系统，维护用户、组织、角色、权限、菜单和基础配置，并能够查看关键操作审计。

### SCN-004：派生真实业务模块

开发者在不修改基础模块内部实现的前提下，新增一个具有前端页面、后端接口、数据库迁移、权限和测试的业务模块。

### SCN-005：裁剪可选模块

开发者不引入某个可选 Maven 模块并移除对应前端模块注册后，系统仍然能够编译、启动和使用其余功能。

### SCN-006：单机和部署运行

开发阶段前后端独立运行；单机模式可以运行一个发布包并使用 SQLite；正式部署可以前后端独立部署并连接外部数据库。

## 5. 已确认方向

以下内容来自已完成的讨论，但本文件整体仍为草稿：

| 领域 | 已确认方向 |
| --- | --- |
| 产品形态 | 完整全栈内部管理系统模板 |
| 产品界面 | 当前包含公开站点、内部工作台和管理控制台；未来可增加独立客户空间 |
| 登录与认证 | 内部人员和管理员共用入口；0.1 使用服务端 Session，长期演进为 OAuth2/OIDC + BFF + JWT 资源服务 |
| 身份与授权 | 部门—用户—角色—权限点；只预置根部门、系统管理员角色和初始化管理员 |
| 后端 | Java 25 LTS、Spring Boot 4.1.x、Maven 多模块、模块化单体；真实拆分后再评估 Spring Cloud |
| 数据访问 | MyBatis-Plus；简单 CRUD 使用 BaseMapper/Lambda Wrapper，复杂查询使用 XML |
| 数据对象 | 只使用 DO 和 DTO |
| 前端 | 单个 Vue 3、TypeScript、Vite SPA；按布局、路由和业务模块区分产品界面 |
| 默认数据库 | 未配置数据库时使用 SQLite 文件库 |
| 外部数据库 | 显式选择 MySQL、Oracle 或 PostgreSQL |
| 数据迁移 | Liquibase |
| Spring AI | 2.0.x 作为未来重点能力；有已确认用例后再引入，不进入 0.1 |
| Python | 仅在明确需要 Python 专属 AI/数据能力时引入 |
| 实现原则 | 控制范围、避免静默兜底、禁止简单问题复杂化 |
| 0.1 范围 | 以公开主页内容发布验证完整 AI 功能产出流水线，详见 `V0_1_SCOPE.md` |

## 6. 已确认的后端模块范围

后端从早期采用 Maven 多模块，按能力纵向拆分，不按 Controller、Service、Mapper 技术层拆分。

完整边界和依赖规则见 [后端模块架构基线](../docs/architecture/BACKEND_MODULES.md)。

### 6.1 基础模块

| 模块 | 职责 | 当前状态 |
| --- | --- | --- |
| `platform-kernel` | 最小公共类型和模块事件基础约定 | 已确认 |
| `platform-web` | HTTP、校验、统一响应和异常边界 | 已确认 |
| `platform-data` | MyBatis-Plus、数据源选择和 Liquibase 运行基础 | 已确认 |
| `platform-security` | 认证与权限校验的基础能力 | 已确认 |

### 6.2 业务模块

| 模块 | 0.1 职责 | 当前状态 |
| --- | --- | --- |
| `module-iam` | 初始化管理员、根部门、用户、角色、登录和权限 | 已确认 |
| `module-file` | 本地图片存储与访问约束 | 已确认 |
| `module-site` | 主页草稿、预览、发布、撤回和公开读取 | 已确认 |
| `module-audit` | 发布与撤回所需的最小审计记录 | 已确认 |

### 6.3 装配模块

| 模块 | 职责 | 当前状态 |
| --- | --- | --- |
| `app-server` | 装配所需模块、聚合配置与迁移并启动 Spring Boot 应用 | 已确认 |

总体依赖方向为 `app-server → 业务模块 → 基础模块`。基础模块不依赖业务模块，业务模块不依赖 `app-server`，跨业务模块只能通过公开 API 或本地模块事件协作。

通知、定时任务、工作流、多租户和 AI 不提前创建空模块，在对应需求进入已确认状态后再增加。当前不引入 Spring Cloud 或其他分布式组件。

## 7. 已确认的前端物理范围

前端采用单个 Vue 应用和一个构建产物，按业务能力组织功能目录。公开站点使用独立公开布局，内部工作台和管理控制台共用登录状态与系统布局。完整说明见 [前端物理结构基线](../docs/architecture/FRONTEND_STRUCTURE.md)。

0.1 的前端业务目录包括：

```text
app
layouts
shared
modules/auth
modules/workspace
modules/iam
modules/file
modules/site
```

前端模块维护自己的页面、路由注册、API、Query Key 和业务组件。0.1 不使用多个前端应用、pnpm 多包工作区、Nuxt、SSR 或静态生成。

未来可以增加与内部账号边界分离的客户空间，但没有真实客户用例前，不创建外部账号、权限、路由和占位页面。

## 8. 首个可用版本范围

0.1 的已确认范围由 [V0_1_SCOPE.md](V0_1_SCOPE.md) 定义。

0.1 不追求一次完成用户、组织、角色、配置、字典、审计、文件和多个公开模板。它只实现支撑“公开主页内容发布”所必需的最小身份、权限、文件、发布和审计能力，并用该闭环验证 AI 高质量产出流水线。

本文件中的完整模块清单属于产品长期方向，不能反向扩大 0.1 范围。

## 9. 产品级验收候选

### AC-001：零配置数据库

未提供任何数据库配置时，首次启动创建 SQLite 数据文件并完成全部迁移；刷新或重启后数据仍然存在。

### AC-002：外部数据库失败可见

提供外部数据库配置但连接失败时，启动必须失败并指出数据库配置或连接问题，不得创建或写入本地 SQLite。

### AC-003：权限以后端为准

未授权用户即使绕过前端菜单直接请求 API，也必须被后端拒绝，并产生可关联的安全或操作记录。

### AC-004：模块可裁剪

移除一个被定义为可选的后端模块依赖和对应前端注册后，其余系统能够完成编译、测试和启动。

### AC-005：派生业务

开发者能够依据文档新增一个完整业务模块，不需要修改 IAM、审计和基础数据模块的内部 Mapper 或表结构。

### AC-006：前后端契约

接口字段和错误发生变化时，OpenAPI、前端类型和相关测试必须同步更新。
