# 非功能需求草案

> 状态：草稿  
> 版本：0.1  
> 适用模块：全项目  
> 关联前端：待建立  
> 关联后端：待建立  
> 关联材料：无

## 1. 目的

本文件描述系统除了“具备哪些功能”之外必须达到的质量属性。当前先确定方向和可验证方式，具体数值目标在真实基线测试后确认，禁止凭空设置性能和覆盖率数字。

## 2. 可启动性

### NFR-BOOT-001：无数据库安装启动

- 开发者不安装数据库服务也能启动完整系统；
- SQLite 驱动和迁移由项目依赖管理；
- 本地数据默认持久化，不因应用重启消失；
- 启动失败必须指出缺少的运行环境或错误配置。

### NFR-BOOT-002：启动说明可执行

- 新开发者只依据 README 和脚本即可完成启动；
- 文档中的命令必须在 CI 或发布检查中验证；
- 禁止依赖作者机器上的隐含环境和手工数据库操作。

## 3. 模块化与可维护性

### NFR-MOD-001：能力模块独立

- 后端模块拥有自己的代码、配置、迁移和测试；
- 模块不直接访问其他模块的内部 Mapper 和 DO；
- 可选模块被移除后，其他模块不能因隐藏依赖而编译失败；
- `app-server` 只负责装配，不承载业务规则。

### NFR-MOD-002：控制实现复杂度

- 实现遵守根开发规范中的最小连贯改动原则；
- 禁止用空壳接口、重复模型和通用基类制造表面分层；
- 方法拆分以业务语义、事务和阅读路径为依据，不按行数机械拆分；
- 发现相邻问题时单独报告，不在当前修改中扩大范围。

## 4. 数据库兼容性

### NFR-DB-001：数据库选择明确

- 完全未配置数据库时使用 SQLite；
- 显式配置外部数据库后禁止回退 SQLite；
- 数据库类型、URL、用户和密码的校验行为一致且可理解。

### NFR-DB-002：结构可迁移

- 所有结构变更通过 Liquibase；
- 已发布变更集不可修改；
- SQLite、MySQL、PostgreSQL 和 Oracle 的差异必须显式处理；
- 破坏性变更必须有历史数据迁移与回滚方案。

### NFR-DB-003：查询可控

- 列表默认分页；
- 禁止 N+1 和循环单条查询；
- 排序字段使用服务端白名单；
- 重要查询的索引与执行计划必须经过验证。

## 5. 安全性

### NFR-SEC-001：后端鉴权

- 菜单和按钮隐藏不能替代后端权限校验；
- 直接调用未授权 API 必须失败；
- 用户、角色和数据范围不能信任前端传值；
- 权限失败不能被空结果或默认成功掩盖。

### NFR-SEC-002：敏感信息保护

- 密码只保存可靠哈希，不保存或记录明文；
- Token、Cookie、密钥和数据库密码不得进入日志；
- DO 不直接作为 API 响应；
- 错误响应不暴露堆栈、SQL、内部路径和连接信息。

### NFR-SEC-003：安全审计

- 登录、权限拒绝和关键管理操作必须能够关联操作者、请求和结果；
- 审计失败不能静默伪装为审计成功；
- 审计数据的保留、脱敏和查询权限需要在审计模块需求中继续确认。

## 6. 可靠性与一致性

### NFR-REL-001：失败可见

- 配置、迁移和连接错误快速失败；
- 查询失败不能返回空列表；
- 禁止无限重试和无提示降级；
- 可选能力降级必须向调用方暴露状态。

### NFR-REL-002：事务一致性

- 同一业务用例中的原子写入由 Service 事务保护；
- 禁止吞掉异常导致事务错误提交；
- 外部调用不应无界地占用数据库事务；
- 批量操作必须定义部分失败行为。

## 7. 前端体验

### NFR-UI-001：状态完整

页面必须明确展示：

- 加载中；
- 无数据；
- 请求失败；
- 无权限；
- 提交中和提交结果。

请求失败禁止显示为无数据。

### NFR-UI-002：数据请求可控

- 服务端状态由 TanStack Query 管理；
- 相同查询可以去重和缓存；
- 条件变化后取消已经无意义的请求；
- 写操作成功后精确失效相关缓存；
- 退出登录后清理用户相关缓存。

### NFR-UI-003：基本可用性

- 表单错误必须定位到对应字段或明确区域；
- 破坏性操作必须二次确认；
- 离开未保存表单时应提醒；
- 键盘操作、焦点和颜色对比的具体标准待组件库确认后补充。

## 8. 性能

### NFR-PERF-001：先建立基线

- 首个版本不凭空承诺响应时间和并发数字；
- 先对登录、用户分页、权限加载和菜单加载建立可重复测试基线；
- 性能目标必须说明数据规模、硬件、数据库和测试方法；
- 性能问题优先通过查询次数、索引、分页和缓存边界解决，不提前引入分布式架构。

### NFR-PERF-002：前端体积与渲染

- 路由页面按需加载；
- 普通列表使用分页，不默认使用实验性虚拟表格；
- 构建产物体积预算在前端骨架形成后基于真实结果确认；
- 禁止为未测量的性能问题提前增加复杂缓存和组件抽象。

## 9. 可测试性

### NFR-TEST-001：按风险验证

- Bug 修复必须有回归测试；
- 权限规则必须有后端测试；
- 复杂 Mapper 使用真实数据库测试；
- 数据库专属 SQL 在对应数据库验证；
- 关键登录和授权链路具备端到端测试；
- 不为追求覆盖率数字测试纯 DTO 和无行为代码。

### NFR-TEST-002：测试真实

- 禁止删除断言、跳过测试或吞异常使测试通过；
- 测试数据表达确定业务场景；
- 测试结果必须可重复；
- CI 和本地使用相同的核心检查入口。

## 10. 可观察性

### NFR-OBS-001：请求关联

- 请求、错误和关键审计记录需要统一关联标识；
- 同一异常只在合适边界记录一次；
- 日志包含足够定位信息，但不包含敏感数据；
- 指标和追踪的具体实现等待工程骨架阶段确认。

## 11. 文档与可派生性

### NFR-DOC-001：文档同步

- 行为、配置、模块边界和数据库结构变化时同步更新相关文档；
- 文档中的启动、迁移和测试命令必须能够执行；
- 派生一个新业务模块所需步骤必须有完整示例；
- 材料、草稿和已确认需求必须能够区分。

## 12. 待量化项目

以下内容需要在可运行骨架和基线测试形成后确认：

1. 目标数据规模；
2. 核心 API 响应时间；
3. 并发用户和吞吐目标；
4. 前端首屏与构建体积预算；
5. 审计数据保留时间；
6. 支持的浏览器最低版本；
7. 数据库最低版本；
8. 备份恢复时间和可接受数据丢失范围；
9. 是否设置代码覆盖率下限。
