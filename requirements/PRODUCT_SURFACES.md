# 产品界面与访问边界

> 状态：已确认  
> 版本：0.1  
> 适用模块：全项目  
> 关联前端：待建立  
> 关联后端：待建立  
> 关联材料：无

## 1. 结论

完整项目包含三个产品界面：

```text
公开站点 Site
内部工作台 Workspace
管理控制台 Admin Console
```

这三个界面是当前产品的使用者和权限边界，不代表必须建设三个独立后端服务或三个前端应用。0.1 采用一个 Vue 应用，具体见 [前端物理结构基线](../docs/architecture/FRONTEND_STRUCTURE.md)。

## 2. 使用者边界

### 2.1 外部访问者

- 外部访问者无需内部账号即可访问公开站点；
- 只能读取已经发布的公开内容；
- 不能访问草稿、内部工作数据和管理能力；
- 当前不规划外部用户注册、社交关系、交易账号和会员体系。

### 2.2 内部使用者

- 内部使用者属于公司、团队或组织成员；
- 通过统一登录入口进入系统；
- 登录后默认使用内部工作台；
- 只能访问被授予的业务功能。

### 2.3 管理人员

- 管理人员同样属于内部人员；
- 与普通内部使用者共用登录入口、身份体系和登录状态；
- 登录后依据权限额外获得对应管理功能和 API 能力；
- 管理身份不等于超级管理员，后端仍按当前操作校验权限。

## 3. 统一登录要求

### REQ-SURFACE-001：内部人员统一登录

- 状态：已确认
- 使用者：内部使用者、内容编辑和系统管理员
- 前置条件：用户具有有效内部账号
- 触发：用户访问登录入口并提交凭据
- 主流程：
  1. 系统验证内部账号；
  2. 系统建立统一登录状态；
  3. 系统加载用户身份和功能权限；
  4. 系统进入内部工作台；
  5. 用户具有管理权限时，同时展示对应管理功能。
- 异常流程：账号无效、凭据错误或认证系统异常时必须明确失败，不能进入匿名兜底账号。
- 权限：后端是最终权限判定方，前端菜单隐藏不能替代 API 鉴权。
- 验收标准：同一账号、同一登录入口和同一登录状态能够访问其工作台能力；授予管理权限后无需切换账号体系即可访问对应管理功能。
- 认证方式：0.1 使用服务端 Session 和安全 Cookie；长期演进边界见 [认证架构基线](../docs/architecture/AUTHENTICATION.md)。

## 4. 公开站点要求

### REQ-SURFACE-002：公开内容访问

- 状态：已确认
- 使用者：未登录的外部访问者
- 前置条件：内容已经发布
- 触发：访问公开页面
- 主流程：系统根据公开路由和展示模板读取已发布内容并返回页面。
- 异常流程：内容不存在、未发布或已撤回时不能泄露草稿和内部数据。
- 权限：公开接口只暴露明确允许公开的数据字段。
- 验收标准：匿名访问者能够看到已发布内容，但无法通过修改 URL 或直接请求接口读取草稿及内部数据。
- 非目标：当前不包含外部访客注册、评论、下单、支付、库存和配送。

## 5. 内容与模板要求

### REQ-SURFACE-003：代码模板与内容发布

- 状态：已确认
- 使用者：具有内容维护权限的内部人员
- 前置条件：系统中存在代码提供的固定主页模板
- 触发：内容维护人员编辑主页内容
- 主流程：
  1. 管理端加载代码定义的固定主页结构；
  2. 用户填写站点名称、简介、主展示图片和联系方式；
  3. 用户预览当前草稿；
  4. 用户发布后，公开站点展示当前公开快照。
- 异常流程：必填内容缺失、图片无效或用户无权限时必须阻止操作并指出原因。
- 权限：后端按当前操作校验主页内容管理权限，不在本需求中预先拆分权限编码。
- 验收标准：修改内容不需要修改页面代码；新增或修改页面结构仍然通过代码和版本控制完成。
- 非目标：0.1 不提供模板选择、任意拖拽、任意组件拼装、自定义脚本或低代码页面编辑器。

## 6. 产品界面职责

| 界面 | 核心职责 | 不负责 |
| --- | --- | --- |
| 公开站点 | 展示已发布内容和公开信息 | 内部业务、草稿、权限管理 |
| 内部工作台 | 当前用户资料和有权限使用的功能入口 | 未授权管理能力 |
| 管理控制台 | 0.1 的用户、角色和主页内容管理 | 部门、配置、字典和完整审计平台 |

## 7. 未来客户空间方向

未来可以增加面向外部客户的登录和客户空间，用于反馈、合作意向等对外业务。外部客户是独立于内部员工的身份类别，不作为内部账号体系中的普通角色，也不进入内部工作台和管理控制台。

该方向当前只作为产品演进边界，不是 0.1 实现需求。0.1 不创建外部账号表、客户权限、客户路由、占位页面和空模块；是否需要客户登录，必须由首个真实外部业务用例决定。

## 8. 范围控制

本需求确认的是产品界面和访问边界，不自动增加以下业务：

- 库存、订单、支付和配送；
- CRM、ERP 或完整餐饮系统；
- 社交关系、评论和外部会员体系；
- 拖拽式页面构建器和低代码平台；
- 为尚未确认的使用者提前建设独立身份系统；
- 三个独立后端服务。

个人博客、团队主页、公司介绍和餐饮展示可以作为未来模板或示例，但必须分别进入需求讨论，不能从本需求直接推导为首版必做模块。
