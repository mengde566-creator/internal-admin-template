> 关联前端：`frontend/src/modules/warehouse/`；知识资料管理页面待建立；导入限制配置页面待建立

## 1. 一句话意图

让获得授权的内部人员通过普通管理页面，安全地导入、预览、确认和导出物品主数据，并上传、预览和发布知识资料；外部文件始终是不可信输入，任何不确定或过期结果都不能直接进入生效数据。

## 2. 首期边界

- 物品主数据支持 `.xlsx` 和 `.csv` 导入，支持标准模板、当前数据和错误报告导出；不导入仓库、库位、库存余额或库存操作。
- 知识资料支持 `.docx`、`.md` 和 `.txt`；`.doc` 只识别并提示转换为 `.docx`；PDF、图片、扫描件、手写件和 OCR 不在本期。
- 首期只提供普通管理页面入口；助手上传、对话驱动导入和助手确认写入不在本期。
- 上传不能直接写物品表或切换知识 ACTIVE 版本。用户必须先看到服务端生成的影响预览，再明确确认。
- 本期没有病毒扫描服务，只承诺真实格式、结构、资源和内容边界校验；页面和接口不得宣称文件已通过病毒扫描或绝对安全。
- 日、周、月数据分析不与本需求合并，另行完成场景、指标和时间边界确认。

## 3. 使用者和权限

| 使用者 | 需要的权限 | 首期能力 |
| --- | --- | --- |
| 仓储主数据维护人员 | `warehouse:master:manage` | 下载模板、按本人可管理范围导出、上传物品文件、查看影响、排除异常行、确认整批写入 |
| 知识维护人员 | `ai:knowledge:manage` | 上传知识文件、查看解析结果、保存草稿、发布当前版本、查看历史版本和来源文件 |
| 系统配置管理员 | `system:config:manage` | 维护受控的导入限制配置组 |
| 其他登录用户 | 无上述权限 | 不显示入口；直接调用接口返回 403，不能通过作业标识推测文件或数据是否存在 |

知识上传和发布不拆分审批角色。拥有 `ai:knowledge:manage` 即视为具有该高级操作权限；发布仍需当前操作者明确二次确认，但不建立审批流或虚构审核人。

## 4. 共用导入作业

### REQ-V02-FILE-001：安全接收与可恢复作业

- 状态：已确认
- 使用者：仓储主数据维护人员、知识维护人员
- 用户目标与已知信息：用户只知道要上传的本地文件和业务用途，不需要提供存储路径、数据库 ID、解析器名称或技术参数。
- 前置条件：用户已登录并拥有目标业务权限；文件符合本期格式范围。
- 触发：用户在对应管理页面选择文件并提交。
- 主流程：
  1. 用户先选择业务入口，再选择文件；系统不要求用户选择内部解析器或数据库表；
  2. 服务端按实际字节和结构识别格式，不信任文件名、扩展名和客户端 MIME；
  3. 文件先进入仅授权用户可访问的隔离区，使用系统随机名称；
  4. 系统创建可恢复的导入作业并显示文件名、业务类型、创建人、创建时间、状态和可执行的下一步；
  5. 刷新页面或重新登录后，用户可从本人可见的作业列表继续处理尚未过期的作业；
  6. 原文件、解析结果、影响预览和最终结果始终绑定同一作业，不能由浏览器自行拼装替换。
- 异常流程：空文件、伪装格式、损坏结构、加密文件、宏、外部关系、嵌入对象、公式错误、压缩炸弹风险、超时、超量或存储失败必须明确拒绝；拒绝不能留下可继续确认的作业或部分最终文件。`.doc`、PDF、图片和扫描件给出受支持格式提示，不尝试隐式转换或 OCR。
- 权限：上传、查看原文件、查看预览、取消和确认每一步均重新校验当前登录用户及目标业务权限；作业创建者身份来自服务端 Session。
- 数据：保存受控原文件、作业状态、格式事实、内容哈希、限制快照、处理摘要和必要错误标识；日志、通用审计和错误响应不保存正文、完整单元格、内部路径、Cookie、密钥或堆栈。
- 验收标准：真实文件从上传到预览可恢复；伪装、损坏、超量和越权文件均在业务写入前失败；重复点击不会产生两个可执行确认；刷新后状态与服务端一致。
- 非目标：对象存储、公共下载、匿名上传、任意压缩包、病毒扫描和通用文件转换平台。

### REQ-V02-FILE-002：导入限制配置

- 状态：已确认
- 使用者：系统配置管理员
- 用户目标与已知信息：管理员在专用“导入限制”配置区调整可理解的容量和保留期，不编辑任意配置 key，也不接触代码硬上限。
- 前置条件：用户拥有 `system:config:manage`。
- 触发：管理员查看或修改导入限制。
- 主流程：
  1. 页面展示服务端登记的固定配置项，包括文件大小、表格最大行数、文档最大字符或片段预算、未确认作业保留期和结果文件保留期；
  2. 每项显示当前值、允许范围、单位和影响说明；
  3. 保存时后端按固定白名单和代码硬上限校验；
  4. 配置更新只影响更新后创建的新作业；每个作业保存创建时的限制快照，处理中不随配置变化漂移；
  5. 达到保留期后，由项目正常清理入口有界清理本模块拥有的作业数据与文件，失败可诊断且不触碰已生效知识和仓储业务数据。
- 异常流程：零值、负值、无界值、超硬上限、未知配置项、单位错误或并发版本冲突明确拒绝；配置缺失不能静默变为无限制。
- 权限：前端隐藏不能代替后端鉴权；其他权限不能修改配置。
- 数据：配置只保存固定数值和版本，不保存路径、密钥、解析规则、权限规则或任意脚本。
- 验收标准：合法配置只作用于新作业；非法配置不生效；旧作业仍按原快照处理；清理只删除到期且未被生效业务引用的作业资产。
- 非目标：通用参数平台、任意 key/value 管理、动态脚本和管理员关闭安全硬上限。

## 5. 物品主数据导入与导出

### REQ-V02-FILE-003：物品模板和数据导出

- 状态：已确认
- 使用者：仓储主数据维护人员
- 用户目标与已知信息：用户希望批量新增或维护物品，能够理解物品编码、名称、基本单位和启停状态，不应理解内部 ID 或数据库版本。
- 前置条件：用户拥有 `warehouse:master:manage`。
- 触发：用户在物品页面选择下载标准模板、导出当前筛选数据或下载某次作业错误报告。
- 主流程：
  1. 标准模板使用固定业务列和简短填写说明；
  2. 当前数据导出复用物品页面筛选语义并由服务端重新鉴权，导出编码、名称、基本单位和状态；
  3. 导出文件可携带由系统维护的受控并发信息，但用户不需要查看或填写内部 ID；
  4. 错误报告按原行号输出错误类别、原因和建议处理方式，可修改后重新上传；
  5. CSV/Excel 输出对可能触发公式的文本进行安全处理，下载文件名由服务端生成。
- 异常流程：无权限、筛选无效、数据查询失败、生成失败或结果已过期分别提示，不能生成空文件冒充成功。
- 权限：导出范围不得超过当前仓储主数据权限；文件链接不可由其他用户猜测或复用。
- 数据：不导出内部数据库 ID、审计字段、历史流水或库存数量。
- 验收标准：用户可完成“下载模板或当前数据 → 离线编辑 → 重新上传”；导出的特殊字符不会在常见表格软件中作为公式执行。
- 非目标：通用报表平台、后台无界全量导出和自动定时发送。

### REQ-V02-FILE-004：自动解析与影响预览

- 状态：已确认
- 使用者：仓储主数据维护人员
- 用户目标与已知信息：用户上传标准模板后直接查看影响，不需要逐列配置；只有文件确实存在歧义时才处理异常。
- 前置条件：安全接收完成，作业类型为物品主数据。
- 触发：系统解析 `.xlsx` 或 `.csv`。
- 主流程：
  1. 系统按标准列名和服务端登记的少量稳定别名自动识别列，列顺序可以不同；
  2. 正常模板不出现列映射步骤；只有一个来源列可能对应多个业务字段，或多个来源列争用同一业务字段时，才要求用户一次性消歧；
  3. 已有物品只按物品编码定位；名称可以重名，绝不作为更新主键；
  4. 服务端把每一行归类为 `CREATE`、`UPDATE`、`DISABLE`、`UNCHANGED`、`INVALID` 或 `CONFLICT`；
  5. 页面先展示总数和各类数量，再允许按分类查看有限分页明细；正常用户优先处理异常，不被迫逐行确认正确数据；
  6. 用户可修正允许修正的输入，或明确排除不准备导入的异常行；重新校验后更新影响摘要；
  7. 只有不存在未处理的 `INVALID` 或 `CONFLICT` 时，作业才能进入待确认状态。
- 异常流程：缺必填列、文件内编码重复、编码或字段非法、状态无法识别、隐藏行或合并单元格造成歧义、多工作表无法唯一确定、错误公式、已有流水物品修改基本单位、仍有库存物品停用、当前数据版本冲突均明确到原行号；禁止静默忽略、自动修正业务值或以模型猜测列含义。
- 权限：预览只展示当前用户有权管理的对象；无权对象不得以候选或错误明细泄露。
- 数据：预览保存规范化业务值、稳定分类、当前事实版本和错误码，不保存公式执行结果、宏、脚本或内部 SQL。
- 验收标准：标准模板无需映射即可产生正确影响摘要；异常只要求用户处理真实差值；重名、重复、旧版本和越权数据均不会自动绑定或进入确认。
- 非目标：任意非标准 Excel 智能 ETL、模型自动映射、人员或部门姓名解析、仓库/库位/库存操作导入。

### REQ-V02-FILE-005：物品整批确认与原子执行

- 状态：已确认
- 使用者：仓储主数据维护人员
- 用户目标与已知信息：用户确认的是页面已经展示的整批影响，不提交内部 ID 或自行计算版本。
- 前置条件：作业处于待确认状态，没有未处理异常，预览未过期。
- 触发：用户查看最终摘要并执行二次确认。
- 主流程：
  1. 服务端使用客户端请求标识保证确认幂等，并以状态 CAS 保证只有一个执行者取得执行权；
  2. 执行前重新校验当前用户权限、作业归属、限制快照、物品编码、行版本、库存和流水约束；
  3. 任一事实与预览不一致时整批停止，不写物品数据，作业返回需要重新预览的明确状态；
  4. 所有有效行在同一仓储业务事务中执行；复用现有物品规则、CAS、审计和物品变更事件，不通过 Mapper 绕过 Service 业务边界；
  5. 全部成功后才把作业标记完成，并显示新增、修改、停用、不变化和排除数量；
  6. 重复确认返回同一最终结果，不重复写入或重复发布事件。
- 异常流程：权限变化、预览过期、其他管理员更新、作业已执行、数据库失败、审计失败或变更事件边界失败均不能形成部分成功；失败后页面保留可诊断结果，并明确是重新预览、重新登录还是稍后重试。
- 权限：确认时重新使用当前 Session 和仓储权限，不信任上传时身份快照授予写权限。
- 数据：物品编码创建后不可修改；已有库存流水时基本单位不可修改；仍有库存时不能停用。作业记录操作摘要和稳定错误，不复制仓储完整历史。
- 验收标准：并发双击只执行一次；确认前数据被另一用户修改时整批零写入；数据库或审计失败时整批回滚；完成后物品页面与搜索索引看到一致结果。
- 非目标：部分成功、后台自动重试、审批、撤销已完成导入和直接导入库存。

## 6. 知识资料导入与发布

### REQ-V02-FILE-006：知识资料确定性解析与草稿预览

- 状态：已确认
- 使用者：知识维护人员
- 用户目标与已知信息：用户知道资料标题、业务文档编码和版本名称；不填写内部文档 ID、版本 ID、向量维度或分块参数。
- 前置条件：Agent/Knowledge 能力已启用，知识 PostgreSQL 可用，用户拥有 `ai:knowledge:manage`。
- 触发：用户在知识资料页面上传 `.docx`、`.md` 或 `.txt`。
- 主流程：
  1. `.docx` 只读取正文、标题层级、段落、列表和表格中的可见文本；`.md` 和 `.txt` 按确定性字符与换行规则读取；
  2. 不执行宏、字段、公式、外部链接、脚本和嵌入对象；不把文档内容解释为系统指令；
  3. 系统显示识别到的标题、章节、字符数、片段数、被忽略的非文本内容和截断状态；
  4. 用户确认文档编码、版本名称和标题，查看与当前 ACTIVE 版本的新增、修改、删除章节摘要；
  5. 保存草稿不会改变当前 ACTIVE 版本，也不会让 Agent 引用草稿；
  6. 相同文档、版本和内容重复提交保持幂等；同一文档版本对应不同内容明确冲突。
- 异常流程：不支持格式、损坏、加密、空正文、超量、危险结构、编码错误、章节无法稳定生成或当前事实变化时明确失败；不调用模型修正文档，不生成看似成功的空草稿。
- 权限：原文件、草稿正文、版本差异和历史版本只对拥有知识管理权限的用户开放；普通仓储查询用户只能通过现有受信知识查询读取 ACTIVE 内容。
- 数据：保留可追溯的原文件引用、内容哈希、解析器版本、章节顺序和草稿状态；不把用户文件标记为 synthetic。
- 验收标准：上传三种受支持格式可得到稳定、可重复的草稿预览；重新加载后预览一致；旧 ACTIVE 仍可正常回答；文档提示注入文本不会触发 Tool、外部调用或系统行为。
- 非目标：PDF、`.doc` 转换、OCR、版式还原、图片提取、模型改写和通用在线文档编辑器。

### REQ-V02-FILE-007：知识索引与发布

- 状态：已确认
- 使用者：知识维护人员
- 用户目标与已知信息：用户确认已预览的草稿成为当前资料，不管理 Embedding 请求或数据库迁移。
- 前置条件：草稿解析完成且仍有效；知识服务与 Qwen Embedding 可用；用户拥有 `ai:knowledge:manage`。
- 触发：用户查看最终文档与版本摘要并二次确认发布。
- 主流程：
  1. 发布前重新校验权限、草稿归属、文档当前版本和内容哈希；
  2. 在数据库事务外按既有受控批次生成 Dense/Sparse Embedding，逐批校验数量、维度和稀疏结构，不自动重试不可重试错误；
  3. 所有片段向量完整后才进入短事务，创建版本、片段和来源关系，并一次切换该文档的 ACTIVE 版本；
  4. 旧版本保留为 INACTIVE，可在管理页面查看但不进入正常检索和引用；
  5. 发布完成后，目录、章节搜索和完整资料读取均只返回新的 ACTIVE 当前事实；
  6. 重复发布同一内容返回同一结果，不重复调用 Embedding 或创建平行版本。
- 异常流程：Provider、数据库、版本并发、向量维度、内容哈希或 ACTIVE 切换失败时，新版本不得部分生效；旧 ACTIVE 继续服务，作业显示明确失败且可由用户在确认当前事实后重试。
- 权限：上传即视为具有发布高级权限，但发布必须由当前受权用户明确确认；系统不得后台自动发布。
- 数据：用户资料与固定 synthetic 资料共用知识版本和检索事实源，但必须保留来源类型；查询仍只返回当前 ACTIVE 且授权可见的受信引用，不能简单删除现有 synthetic 过滤而放宽信任边界。
- 验收标准：发布前旧版持续可查；发布成功后所有入口统一看到新版；任一向量批次或事务失败时旧版仍正常且新版不可查；重复发布不产生重复版本或重复 Provider 调用。
- 非目标：审批流、自动抓取、自动发布、模型自动改写、病毒扫描和运行期任意模型切换。

## 7. 页面与恢复要求

### REQ-V02-FILE-008：普通页面完成整条任务

- 状态：已确认
- 使用者：仓储主数据维护人员、知识维护人员
- 用户目标与已知信息：用户从已有物品页面或知识资料管理页完成全部操作，不进入助手，也不理解后台状态机。
- 前置条件：对应权限和服务可用。
- 触发：用户点击“导入/导出”或“上传知识资料”。
- 主流程：
  1. 页面提供清楚的格式说明、模板下载和限制摘要；
  2. 正常文件采用“选择文件 → 自动解析 → 查看影响 → 确认”的短路径；
  3. 只有真实异常才展开修正、排除或歧义选择，正常用户不逐列映射、不逐行批准；
  4. 上传、解析、等待处理、待确认、执行中、完成、失败、取消和过期均有明确状态；
  5. 用户离开页面或刷新后可恢复作业；执行中按钮不可重复点击；
  6. 失败提示说明失败阶段、受影响内容和下一步，不用“操作失败”代替；
  7. 完成后可以返回物品列表或知识版本页核对真实结果。
- 异常流程：401、403、文件拒绝、解析失败、业务异常、并发冲突、Provider 故障、数据库故障和过期必须区分；失败不得显示为零变化或成功。
- 权限：入口按权限隐藏，路由与 API 仍由后端鉴权；浏览器不能通过篡改作业 ID 查看其他用户文件或结果。
- 数据：前端不长期保存完整原文件、正文或全量解析数据，只读取服务端有界分页和摘要。
- 验收标准：以真实浏览器完成物品导入导出和知识上传发布两条用户链，并覆盖刷新恢复、重复点击、过期、无权限、异常文件和并发变化；不能用组件存在或 HTTP 200 代替用户结果。
- 非目标：助手入口、拖拽工作流、通用低代码映射器和移动端专属流程。

## 8. 跨需求安全与验收矩阵

正式实现必须至少证明：

1. 真实扩展名伪装、损坏压缩结构、压缩炸弹边界、加密/宏/外部关系和超量输入在业务写入前拒绝；
2. 文件、作业、预览、下载和确认均有服务端权限及归属校验；
3. 正常标准模板无需列映射，异常才要求用户处理；
4. 物品编码唯一定位，名称重名不自动绑定，内部 ID 不进入用户文件；
5. 物品确认时权限、版本、库存和流水事实变化会整批零写入；
6. 同一确认请求和并发确认只执行一次；
7. 知识草稿不影响 ACTIVE，发布失败不产生半索引，旧 ACTIVE 持续服务；
8. 重复知识内容不重复 Embedding；用户资料来源不会伪装为 synthetic；
9. CSV/Excel 导出不触发表格公式执行；错误报告不泄露无权数据；
10. 配置变化只影响新作业，硬上限不可由管理员关闭，到期清理不删除生效业务事实；
11. SQLite、MySQL、PostgreSQL 和 Oracle 的业务作业结构与事务语义使用共同能力；知识向量仍按已确认规则限定 PostgreSQL；
12. 全程无 OCR、病毒扫描和助手文件入口，不以未实现能力写入提示或验收结论。

## 9. 明确非目标与后续讨论

- 仓库、库位、库存余额、入库、出库、调拨、盘点、人员、部门、客户和订单批量导入；
- PDF、旧版 `.doc` 转换、图片、扫描件、手写件和 OCR；
- 病毒扫描服务、对象存储和文件内容净化平台；
- 依靠聊天模型识别表头、修复数据、决定业务对象或执行写入；
- 助手上传、助手确认、助手自动导入；
- 日、周、月分析、临时文件问答和通用报表；
- 部分成功、自动审批、自动发布、后台无限重试和导入撤销。

OCR 与图片材料识别留到客户/订单业务阶段重新讨论，不从本需求提前建立模型或解析接口。
