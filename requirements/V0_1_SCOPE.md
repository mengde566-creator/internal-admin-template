## 1. 版本目标

0.1 不以功能数量为成功标准。它使用一个真实、完整且范围受控的业务闭环，验证 AI 能否依据已确认需求，稳定产出数据库、后端、API、前端、权限、测试和文档，并通过统一质量门禁。

0.1 的首要交付是可复用模板底座，公开主页闭环是用于验证底座的参考业务。后续版本不得因为参考主页已经存在，就默认继续扩展建站功能；新增工作的优先判断顺序是模板可启动、可派生、可裁剪、可验证，然后才是参考业务增强。

0.1 的唯一业务闭环是：

```text
内部人员统一登录
→ 进入工作台和内容管理
→ 编辑公开主页内容
→ 上传展示图片
→ 保存草稿
→ 预览
→ 发布
→ 外部访问者查看已发布主页
→ 修改草稿不影响线上内容
→ 撤回后停止公开
```

## 2. 使用者

| 使用者 | 0.1 中的能力 |
| --- | --- |
| 外部访问者 | 匿名访问已经发布的公开主页 |
| 普通内部用户 | 由管理员创建；统一登录、查看个人信息和有权限使用的功能导航 |
| 内容发布人员 | 编辑、预览、发布和撤回公开主页内容 |
| 系统管理员 | 初始化系统、管理用户和角色、通过角色授予权限，并按保护与引用规则删除用户或角色 |
| 独立开发者 | 启动项目并按流水线完成、验证和追踪该功能 |

## 3. 工程基础范围

0.1 后端采用已确认的 Spring Boot 模块化单体和 Maven 多模块边界，详见 [后端模块架构基线](../docs/architecture/BACKEND_MODULES.md)。本版本不引入 Spring Cloud 和微服务基础设施。

0.1 前端采用一个 Vue 3、TypeScript、Vite SPA，公开区域与登录后区域通过布局和路由区分，详见 [前端物理结构基线](../docs/architecture/FRONTEND_STRUCTURE.md)。本版本不创建外部客户账号和客户空间。

### REQ-V01-001：零数据库安装启动

- 状态：已确认
- 使用者：独立开发者
- 前置条件：具备项目明确要求的 Java 和前端运行环境
- 触发：首次启动项目且未提供外部数据库配置
- 主流程：系统创建项目本地 SQLite 数据文件，执行 Liquibase 迁移并启动后端和前端。
- 异常流程：运行环境缺失、数据目录不可写或迁移失败时必须明确失败，不能返回假成功。
- 验收标准：开发者无需安装数据库服务即可完成首次启动；重启后数据继续存在。
- 非目标：0.1 不承诺 MySQL、Oracle 和 PostgreSQL 的完整兼容验证。

### REQ-V01-002：完整工程质量入口

- 状态：已确认
- 使用者：独立开发者、AI
- 主流程：项目提供统一的构建、类型检查、迁移检查、测试和验收入口。
- 异常流程：任一必选检查失败时，流水线失败，禁止通过跳过检查继续交付。
- 验收标准：同一组核心命令可以在本地和 CI 执行，并产生明确结果。
- 非目标：0.1 不建设独立的 AI 编排平台和可视化流水线产品。

## 4. 最小身份与工作台范围

0.1采用部门—用户—角色—权限点模型，只预置根部门、系统管理员角色和初始化管理员，不提供部门管理页面。完整边界见 [0.1身份与授权范围](iam/IDENTITY_AUTHORIZATION.md)。

### REQ-V01-003：初始化管理员和统一登录

- 状态：已确认
- 使用者：系统管理员、普通内部用户、内容发布人员
- 主流程：
  1. 首次运行完成管理员初始化；
  2. 内部人员通过同一个登录入口提交凭据；
  3. 系统建立登录状态并加载当前用户权限；
  4. 登录成功后进入内部工作台；
  5. 具有管理权限的用户看到对应管理功能。
- 登录安全：具有 `system:config:manage` 权限的管理员可以在专用“登录安全”页面启用或停用 `force_password_change`；该页面不得提供任意参数新增、删除、键编辑或其他通用配置能力。
- 异常流程：凭据错误或认证异常时必须明确失败，不能进入匿名或默认账号。
- 权限：后端负责最终权限校验；登录安全维护要求 `system:config:manage`。
- 验收标准：普通内部用户与管理人员使用同一入口；管理能力只对具有相应权限的用户开放；登录安全入口只展示并维护 `force_password_change`。
- 认证方式：内部浏览器使用服务端 Session 和安全 Cookie；0.1 不签发 JWT，不建设 OAuth2/OIDC 授权服务器，具体见 [认证架构基线](../docs/architecture/AUTHENTICATION.md)。

### REQ-V01-004：最小内部工作台

- 状态：已确认
- 使用者：已登录内部人员
- 主流程：工作台展示当前用户基本资料和有权限使用的功能导航。
- 权限：用户不能通过直接输入路由或调用 API 进入未授权管理功能。
- 验收标准：普通用户看不到内容管理入口；被授予内容权限后可以使用对应入口和 API。
- 非目标：0.1 不包含待办、通知、统计大屏、部门管理页面、岗位、部门数据范围和其他实际业务模块。

### REQ-V01-004A：最小用户与角色维护

- 状态：已确认
- 使用者：具有用户或角色管理权限的系统管理员
- 主流程：管理员可以创建、编辑、查询用户和角色，并为用户分配角色、为角色配置代码中注册的权限。
- 删除：删除用户使用软删除，已删除用户不再出现在正常查询结果中且不能登录；删除角色前必须校验不存在有效用户引用，满足条件后删除角色及其权限关联。
- 异常流程：不得删除初始化管理员或当前登录用户；角色仍被有效用户引用时必须拒绝，并指出引用该角色的用户。
- 权限：用户维护要求 `iam:user:manage`，角色维护要求 `iam:role:manage`；后端负责最终校验。
- 审计：用户和角色删除成功时分别记录 `USER_DELETE`、`ROLE_DELETE` 操作审计。
- 验收标准：删除用户不会破坏历史审计；被软删除用户的残留角色关联不阻塞角色删除；被有效用户引用的角色不能删除。
- 非目标：0.1 不提供用户恢复、回收站、批量删除、角色继承、数据范围和部门管理。

## 5. 公开主页范围

### REQ-V01-005：代码定义主页布局、配色与内容区块

- 状态：已确认
- 使用者：外部访问者、内容发布人员
- 主流程：代码提供 `GRID_SPLIT`、`BANNER_SPLIT` 两种固定主页布局；内容发布人员编辑站点名称、简介、主展示图片和联系方式，选择 `GRAPHITE`（黑白）或 `AZURE`（蓝白）配色，并维护 `ABOUT`、`SERVICE`、`NEWS`、`CONTACT` 四种固定类型的内容区块。区块支持新增、修改、删除、排序和可选配图。
- 数据与发布：布局、配色和区块随草稿整体保存；发布时作为完整公开快照原子复制，草稿修改不影响已经发布的公开主页。
- 验收标准：公开页面能够在常见桌面和移动宽度下阅读；预览立即使用草稿的布局、配色和区块；公开主页只在成功发布后变化；区块顺序与保存顺序一致。
- 非目标：0.1 不提供任意颜色输入、主题编辑器、主题表、动态 CSS/JSON、模板选择器、拖拽布局、自定义组件、自定义脚本、区块类型插件化和独立区块 CRUD 接口。

### REQ-V01-006：本地展示图片上传

- 状态：已确认
- 使用者：内容发布人员
- 主流程：授权用户上传符合限制的展示图片，系统保存文件并返回可用于预览和发布的引用。
- 异常流程：文件类型、大小、内容或存储失败时必须明确拒绝，不能留下可公开访问的部分文件。
- 权限：上传和使用图片都需要内容维护权限；公开端只能读取已经随内容发布的图片。
- 验收标准：有效图片可以用于主页预览和发布；未发布内容引用的图片不会泄露受保护信息。
- 非目标：0.1 只支持本地文件存储，不引入对象存储和图片处理流水线。

## 6. 草稿与发布范围

### REQ-V01-007：草稿保存和预览

- 状态：已确认
- 使用者：内容发布人员
- 主流程：用户编辑主页内容、选择代码定义的配色并保存草稿；预览展示当前草稿内容与配色效果。
- 异常流程：必填内容缺失、图片无效或保存失败时必须指出原因。
- 权限：只有具有内容维护权限的内部用户可以读取和修改草稿。
- 验收标准：修改草稿不会改变外部访问者当前看到的已发布主页。

### REQ-V01-008：发布和撤回

- 状态：已确认
- 使用者：具有发布权限的内部人员
- 主流程：
  1. 系统校验草稿完整性和发布权限；
  2. 用户确认发布；
  3. 系统将完整草稿内容与配色原子更新为当前公开快照；
  4. 系统记录发布人和发布时间；
  5. 外部访问者读取更新后的公开快照。
- 异常流程：校验、权限或持久化失败时，本次发布整体失败，当前公开快照继续有效。
- 撤回：授权用户撤回后，公开接口停止返回该内容，但草稿仍保留供后续修改。
- 验收标准：未发布修改不影响线上内容；发布失败不产生半公开状态；撤回后匿名访问不能继续获取内容。
- 非目标：0.1 不提供完整历史版本浏览、多人协同编辑和定时发布。

### REQ-V01-009：发布权限和审计

- 状态：已确认
- 使用者：内容发布人员、系统管理员
- 主流程：系统按当前操作校验所需权限，并记录发布与撤回结果。
- 异常流程：无权限的用户直接调用 API 时必须被后端拒绝，不能依赖前端隐藏按钮。
- 验收标准：能够关联操作者、时间、动作、目标内容和结果；普通用户无法越权发布。
- 非目标：0.1 不建设完整通用审计查询平台，只实现该闭环所需的最小记录和验证。

## 7. AI 功能产出流水线

### REQ-V01-010：可重复的单功能流水线

- 状态：已确认
- 使用者：独立开发者、AI
- 前置条件：功能需求和验收标准已经确认
- 主流程：
  1. 读取已确认需求和开发规范；
  2. 输出影响范围和预计修改文件类型；
  3. 提出表结构及迁移方案并等待确认；
  4. 新增 Liquibase 变更并验证迁移；
  5. 生成后端模块代码和测试；
  6. 生成 OpenAPI 契约；
  7. 生成前端功能和测试；
  8. 执行质量门禁；
  9. 检查越界修改、错误兜底和无意义抽象；
  10. 输出需求到代码和测试的验收报告。
- 异常流程：任何需要确认的前置步骤未通过时必须停止，禁止用猜测或默认值继续生成。
- 验收标准：公开主页内容发布的每项已确认需求都能追踪到数据库、后端、API、前端、权限、测试和验收结果。
- 非目标：0.1 不支持多个未验证需求的并行批量生成。

## 8. 质量门禁

0.1 流水线至少检查：

- 修改是否超出已确认需求；
- 表结构是否先提出并确认；
- Liquibase 是否能够从空库完成迁移；
- 是否存在循环查询、N+1 或无界查询；
- 后端编译、测试和 Javadoc 链接是否有效；
- 前端类型检查、测试和构建是否通过；
- OpenAPI 与前端类型是否一致；
- 权限是否由后端执行；
- 草稿、发布版本和公开读取是否隔离；
- 是否存在异常吞噬、空结果兜底和无界重试；
- 是否生成死代码、空模块和无调用方抽象；
- 实际验证结果是否被如实记录。

## 9. 明确不包含

0.1 不包含：

- 完整用户档案、组织部门、岗位、数据范围和高级角色权限管理平台；0.1只实现已确认的最小用户与角色管理；
- 通用参数配置、数据字典、通知、定时任务和完整审计平台（仅保留首次登录强制改密所需的 `force_password_change` 及其专用“登录安全”页面，不构成通用参数平台）；
- 文章、分类、标签和完整博客；
- 公司、团队、餐饮等多套公开模板；
- 外部访客注册、评论、点赞和会员体系；
- 库存、订单、支付和配送；
- 多租户、工作流和消息队列；
- 低代码、拖拽页面和任意组件编排；
- Python 或 AI 业务模块；
- 微服务和分布式部署；
- MySQL、Oracle、PostgreSQL 的完整兼容承诺；
- 多功能并行批量生成平台。

## 10. 版本完成标准

0.1 只有同时满足以下条件才算完成：

1. 独立开发者无需安装数据库即可启动完整项目；
2. 内部用户和管理人员能够通过统一入口登录；
3. 普通用户无法越权进入内容管理和发布能力；
4. 授权用户能够编辑、选择配色、上传图片、保存草稿和预览；
5. 发布后匿名访问者能够看到新内容；
6. 草稿内容或配色修改不影响已发布页面；
7. 发布失败时旧版本继续有效且不存在半发布数据；
8. 撤回后匿名访问者无法继续读取该内容；
9. 发布和撤回具有最小可验证审计记录；
10. 完整功能通过需求、迁移、后端、API、前端、权限和测试质量门禁；
11. AI 产出过程能够生成可审查的范围说明和验收报告；
12. 0.1 明确不包含的功能没有以空模块、占位代码或未来兼容层形式进入项目。
