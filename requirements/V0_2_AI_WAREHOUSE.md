# 0.2 通用 AI 能力体系与仓储业务适配

> 状态：已确认
> 版本：0.2
> 适用模块：通用 AI 能力、IAM、仓储参考业务
> 关联前端：`frontend/src/modules/` 下的 AI 通用交互与仓储业务资产；精确目录待实现设计确认
> 关联后端：`module-agent`、`module-knowledge`、`module-ai-observability`、`module-warehouse`、仓储 Agent 适配模块；均待建立
> 关联材料：[`docs/PROJECT_VISION.md`](../docs/PROJECT_VISION.md)、[`docs/architecture/AI_CAPABILITY_SYSTEM.md`](../docs/architecture/AI_CAPABILITY_SYSTEM.md)、[`docs/architecture/DEPARTMENT_WAREHOUSE_DESIGN.md`](../docs/architecture/DEPARTMENT_WAREHOUSE_DESIGN.md)、[`docs/frontend/WAREHOUSE_UI_DESIGN.md`](../docs/frontend/WAREHOUSE_UI_DESIGN.md)
> 更新日期：2026-08-15

## 1. 一句话意图

建立一套不绑定仓储领域、可以继续接入其他业务模块的通用 AI 能力体系，并以仓储作为第一个真实业务适配和复用验证样例。

## 2. 已由项目负责人确认的方向

- 通用 AI 体系通过业务适配层接入业务模块，AI 核心不得包含仓库、库存等领域规则；
- 0.2 以仓储作为第一个业务模块和验证样例；
- Agent 默认关闭，关闭时不得破坏当前 SQLite 零配置启动；
- 聊天模型首先接入 DeepSeek 外部 API；
- 知识来源先使用明确标记的模拟材料，向量存储使用 PostgreSQL 与 pgvector；
- 可以为知识库单独配置 PostgreSQL；业务库已经是 PostgreSQL 且未单独配置知识库时，默认复用业务 PostgreSQL；
- AI 首版不执行仓储领域写操作；用户通过人工页面完成写操作；
- 交互采用 A+B 组合：常驻业务侧栏可以收为轻量对话框，支持查询、复制和打开人工页面，主页面保持可见、可继续操作；
- 模型记忆按最后活动时间计算空闲TTL，默认4小时并作为部署参数；长期聊天历史默认保留180天；
- 部门采用树结构；普通员工只查询本部门数据，系统管理员可以查询全部门，部门树不自动授予下级部门数据权限；
- 部门同时提供启停和受保护软删除；ROOT、有子部门、有效用户或仓库引用时禁止删除；
- 仓库归属部门，库位通过仓库继承部门，物品主数据全局共享，库存通过库位归属部门；
- 仓储人工写范围包括入库、出库、调拨和盘点；
- 入库、出库、调拨和盘点支持有限多明细、整单备注和逐行备注；
- 库存数量、操作数量和移动差异采用总19位、4位小数的精确十进制语义；
- 用户身份由服务端从当前 Session 认证结果取得，可以从 Controller 以可信参数形式显式传到后续 Service 和工具调用链；
- 需要项目内独立的 AI 观测模块，完整记录链路、回复效果和异常；不建设独立外部观测项目；
- AI观测运行与步骤保留90天，反馈和评测保留180天；默认不复制保存问题与回复正文；
- DeepSeek使用Flash模型；该示例项目允许用户问题、业务工具结果和知识片段发送给外部模型，不设置业务字段合规过滤；Cookie、Session、密钥和系统凭据仍禁止发送；
- Embedding模型使用阿里云百炼`qwen3.7-text-embedding`，固定1024维，通过外部API生成知识与查询向量；
- 用户调换部门后，历史对话仍仅本人可见；旧历史不自动进入新Memory，历史中的业务对象重新打开时按当前权限校验。

## 3. 产品范围

### REQ-V02-AI-001：Agent 可选启用

- 状态：已确认
- 使用者：模板使用者、系统运维人员、内部员工
- 前置条件：应用已按现有方式正常运行；Agent 配置默认关闭
- 触发：部署配置显式启用 Agent
- 主流程：
  1. Agent 关闭时，不创建模型客户端、知识向量存储和 Agent 对话入口；
  2. Agent 关闭时，不展示 AI 侧栏入口；
  3. Agent 启用时，启动阶段校验模型和知识库必需配置；
  4. 配置成立后才开放 AI 入口。
- 异常流程：配置缺失、知识库连接失败或迁移失败时必须明确启动失败，不得静默改用内存向量库、SQLite 向量实现或其他模型。
- 权限：部署配置不由普通用户修改。
- 数据：关闭状态不产生 AI 会话、知识和观测数据。
- 验收标准：未配置外部模型与知识 PostgreSQL 时，默认 SQLite 应用仍可启动并完成原有功能；显式启用但配置不完整时启动失败且原因可识别。
- 非目标：运行时动态安装、卸载插件或切换 Agent 实现。

### REQ-V02-AI-002：A+B 业务侧栏交互

- 状态：已确认
- 使用者：具有仓储查询权限的内部员工
- 前置条件：用户已登录，Agent 已启用
- 触发：用户在仓储页面展开侧栏或轻量对话框并提交问题
- 主流程：
  1. 宽屏使用停靠式侧栏，侧栏与主操作页面同时可见；
  2. 侧栏可折叠为轻量入口，折叠不销毁当前对话和结果；
  3. 窄屏允许使用覆盖式抽屉，但不得改变后端行为；
  4. 回复文本按流式增量展示；
  5. 业务结果使用固定类型卡片展示；
  6. 用户可以复制字段或整张卡片；
  7. 用户可以通过受控动作打开仓储详情或人工操作页面；
  8. 模型回复期间，主页面仍可浏览和人工操作。
- 异常流程：未登录、无权限、无数据、模型失败、知识不可用、业务查询失败和流式中断必须使用不同状态表达。
- 权限：前端隐藏和禁用只改善体验，后端必须重新鉴权。
- 数据：首版只允许显式白名单页面上下文，不发送未提交表单和敏感字段。
- 验收标准：用户可完成“提问 → 流式回复 → 查看卡片 → 复制 → 打开人工页面”，同时主页面状态不被对话阻断或重置。
- 非目标：模型生成任意 HTML、任意 Vue 组件、任意 URL、拖拽工作流或全局替换现有系统布局。

### REQ-V02-AI-003：仓储只读工具

- 状态：已确认
- 使用者：具有相应仓储查询权限的内部员工
- 前置条件：用户身份和允许的数据范围已经由服务端解析
- 触发：Agent 判断问题需要实时仓储事实
- 主流程：首版至少支持物品定位、按物品查询库存、按位置查询内容、查询近期库存移动四类只读能力；工具通过仓储模块公开 API 取得事实并返回稳定 DTO。
- 异常流程：无权限必须拒绝；无数据是成功空结果；业务错误、超时和系统错误分别表达；模型不得通过修改部门参数重试越权。
- 权限：工具不得接受模型或浏览器提供的可信用户 ID、部门范围和权限集合。
- 数据：实时库存只从仓储业务库和正式业务 Service 查询，不写入或从向量库反推。
- 验收标准：所有工具调用均能关联当前用户、部门范围、运行 ID 和结果状态；代码中不存在 Agent 直接访问仓储 Mapper、DO 或表的路径。
- 非目标：AI 创建、修改、提交、撤销库存记录，持久化业务草稿，直接 SQL 或 NL2SQL。

### REQ-V02-AI-004：人工业务操作衔接

- 状态：已确认
- 使用者：具有仓储写权限的内部员工
- 前置条件：Agent 返回受信业务卡片或页面动作
- 触发：用户点击“打开详情”或“打开人工操作页面”
- 主流程：前端用受控 `routeKey + params` 映射项目路由；进入页面后按现有 Controller、Service、权限、CSRF、校验、事务和审计执行人工操作。
- 异常流程：路由类型未知、参数不合法、对象不存在或无权访问时明确拒绝。
- 权限：打开页面不等于获得写权限；页面加载和提交时重新鉴权。
- 数据：首版不由 AI 自动提交，也不持久化 AI 草稿。
- 验收标准：篡改路由参数或复制他部门对象 ID 不能绕过页面权限。
- 非目标：首版表单自动预填、AI 写工具和人机审批恢复流程。

### REQ-V02-AI-005：可信用户与部门范围

- 状态：已确认
- 使用者：所有仓储 Agent 用户
- 前置条件：现有 Session 已完成认证
- 触发：Controller 接受一轮新的 Agent 请求
- 主流程：
  1. Controller 从当前认证上下文取得用户 ID；
  2. 服务端通过 IAM 公开能力解析当前有效用户、部门和权限；
  3. 形成不可变的可信调用者参数并传给 Agent Service；
  4. 异步、流式、检索和工具调用均显式携带该参数或其受控派生对象；
  5. 仓储 Service 对部门范围和业务权限执行最终校验。
- 异常流程：Session 失效、用户停用、部门失效、权限不足或会话不属于当前用户时拒绝请求。
- 权限：模型和前端不能覆盖可信调用者参数。
- 数据：首版仓储数据按部门过滤；普通员工只查本部门，系统管理员可查全部门；部门树不自动扩大查询范围。
- 验收标准：两个不同部门用户并发查询不串线；伪造用户或部门参数无效；异步线程不依赖自然继承 `SecurityContextHolder`。
- 非目标：第二套 IAM、模型代替业务授权、仅靠前端过滤部门。

### REQ-V02-AI-006：模拟知识与引用

- 状态：已确认
- 使用者：仓储业务用户、知识维护人员
- 前置条件：Agent 已启用，知识 PostgreSQL 可用
- 触发：用户询问仓储制度、编码或操作规则
- 主流程：
  1. 模拟知识明确标记为合成材料；
  2. 文档具有来源、版本、生效状态和更新时间；
  3. 检索结果带文档、版本和片段标识；
  4. 回答展示可核对引用；
  5. 失效版本不得进入正常回答。
- 异常流程：知识库不可用、没有命中和命中失效版本分别表达；禁止把实时库存问题交给向量检索回答。
- 权限：首版公共模拟知识默认对已获仓储查询权限的用户可见；未来部门知识需单独确认。
- 数据：知识数据存放在 PostgreSQL/pgvector；结构和基础数据通过知识模块自己的 Liquibase 入口管理。
- 验收标准：固定问题可以追溯到正确文档和版本；停用文档不再命中；知识故障不会阻断人工仓储页面。
- 非目标：OCR、大规模多格式 ETL、自动抓取企业资料、自动改写知识和实时库存向量化。

### REQ-V02-AI-007：短期记忆与长期历史分离

- 状态：已确认
- 使用者：Agent 用户
- 前置条件：用户拥有当前对话
- 触发：用户继续当前对话或打开历史对话
- 主流程：
  1. 完整用户消息与最终助手消息进入长期历史；
  2. 模型只读取当前用户、当前对话、当前有效记忆段中的有限消息；
  3. 记忆窗口按小时配置，并同时受最大消息数或 Token 预算限制；
  4. 记忆到期后历史仍可查看，但后续消息从空上下文开始；
  5. 长期历史不得自动摘要或回灌模型。
- 异常流程：历史读取失败、写入失败、流式中断和客户端取消分别记录；半条回复不得标记为完整回复。
- 权限：用户只能读取和继续自己的对话；用户调岗后旧History仍仅本人可见，但其中业务对象再次打开时按当前权限重新校验；观测管理员查看内容需要独立权限。
- 数据：History 是唯一完整消息事实源；Memory 是运行时选择结果，不建立第二份完整聊天库。
- 验收标准：可控时间测试证明窗口内可以承接上下文，窗口外不回灌但历史仍显示。
- 非目标：长期偏好、跨会话记忆、自动总结旧对话、向量化个人记忆。

### REQ-V02-AI-008：完整 AI 观测链路

- 状态：已确认
- 使用者：AI 观测管理员、评测人员
- 前置条件：Agent 请求已通过入口认证和会话归属检查
- 触发：一次 Agent 运行开始
- 主流程：
  1. 为每次运行生成唯一 `runId`；
  2. 按顺序记录模型、检索、工具、流式传输和历史持久化步骤；
  3. 记录耗时、Token、模型、工具名、检索引用标识、结果状态和稳定错误分类；
  4. 支持用户对已完成回复点赞、点踩和选择原因；
  5. 支持基于版本化样本运行离线评测；
  6. 管理端提供概览、运行列表、运行时间线和评测结果。
- 异常流程：观测运行无法创建时不得调用模型；运行中观测无法形成终态时不得把本轮显示为完整成功。
- 权限：普通用户只能反馈自己的已完成回复；管理页和内容跳转使用独立权限。
- 数据：默认不复制保存完整 prompt、completion、工具参数/结果、知识片段、Cookie、Session ID、密钥、SQL 和堆栈。
- 保留：运行与步骤默认保留90天，在线反馈和离线评测结果默认保留180天；到期清理由模块自身负责。
- 验收标准：即使底层 trace/span 在流式线程切换中断开，仍能按 `runId + stepId + parentStepId + sequence` 重建完整有序链路；每种异常能定位到唯一阶段和稳定错误码。
- 非目标：Langfuse 等独立平台、通用日志平台、在线 Prompt 编辑器、自动训练、每个 Token 单独落库。

### REQ-V02-AI-009：可复用业务接入

- 状态：已确认
- 使用者：后续模块开发者
- 前置条件：业务模块拥有稳定公共查询 API
- 触发：新的业务模块接入通用 AI 体系
- 主流程：业务通过独立适配资产提供工具描述、工具执行、卡片映射和受控页面动作；通用 Agent、Knowledge 和Observability 不因接入新业务而修改领域逻辑。
- 异常流程：适配器冲突、工具名重复、卡片类型未注册或权限契约缺失时启动或装配失败，不静默忽略。
- 权限：每个适配器调用对应业务 Service 完成最终授权。
- 数据：业务模块拥有自己的数据；通用 AI 模块只保存会话、知识和观测各自拥有的数据。
- 验收标准：移除仓储适配后，三个通用 AI 后端模块中不存在仓储领域依赖并仍可独立构建；在第二个真实业务消费者出现前，只能称“按可复用边界设计”，不得宣称跨业务复用已经完成工程证明。
- 非目标：动态插件市场、运行时上传插件、脚本工具和跨语言远程插件协议。

## 4. 知识 PostgreSQL 配置规则

配置解析采用唯一确定路径：

1. Agent 关闭：不解析知识数据源，不连接 PostgreSQL；
2. Agent 开启且提供知识数据源配置：使用该配置，失败即启动失败；
3. Agent 开启、未提供知识数据源、业务主库为 PostgreSQL：复用业务 PostgreSQL，并使用知识模块独立的结构归属和 Liquibase 迁移入口；
4. Agent 开启、未提供知识数据源、业务主库不是 PostgreSQL：启动失败并说明必须配置知识 PostgreSQL；
5. 禁止失败后改用其他数据库或内存实现。

复用业务 PostgreSQL 不等于知识表归业务模块所有，也不意味着业务事务和知识摄取自动成为同一事务。

## 5. 仓储首版业务范围

首版仓储最小对象为：部门、物品、仓库或存储位置、当前库存和库存移动记录。实时库存查询必须使用正式业务 Service。

部门使用最小完整树模型：部门编码、名称、父部门、同级排序、启停状态和软删除标记；必须拒绝把部门移动到自身或后代节点下。ROOT、有未删除子部门、有效用户或仓库引用时禁止删除；删除不级联、不迁移引用，也不复用原部门编码。首版不建设岗位、多部门兼职、闭包表、物化路径、通用数据权限引擎和下级部门自动继承授权。

仓库归属一个部门，库位通过仓库继承部门，物品主数据全局共享，库存通过库位自然归属部门。禁止在库位和所有仓储表中机械重复`departmentId`；历史库存移动需要保留发生时可追溯的业务归属。

人工页面提供入库、出库、调拨和盘点。四类动作支持有限多明细、整单备注和逐行备注；提交成功后直接生效，首版不设置草稿、审批或复核流程。出库和调拨必须在仓储Service中校验可用库存，禁止产生负库存；盘点以差异移动记录调整余额，禁止绕过流水直接覆盖库存。

库存移动记录作为已发生事实，0.2不提供修改或删除入口。发现入库、出库、调拨或流水记录错误时，不修改旧记录；通过新的盘点调整实际余额，必须填写调整原因并关联原操作。原操作详情应能反向看到后续调整记录。当前不建设撤销或冲正流程。四类动作必须形成库存移动记录并按仓储业务规则更新库存；AI首版不得执行这些动作。批次、序列号、保质期、采购销售订单、成本计价、条码、自动补货暂不进入0.2首版。

所有数量统一使用精确十进制，最多保留4位小数。超过4位小数的请求必须拒绝，不得静默舍入；Java禁止使用`float`或`double`承载库存数量。API和前端必须避免JavaScript浮点转换造成精度损失。四种目标数据库统一使用四位缩放BIGINT物理存储，最大绝对值为`922337203685477.5807`；余额和实盘数量不得小于0，Service必须明确拒绝缩放及加减溢出。

## 6. 回复质量判定

质量判断按以下顺序执行：

1. 确定性安全与契约：部门不越权、未调用写工具、工具与参数正确、实时事实与业务 API 一致、引用版本有效；
2. 用户在线反馈：赞踩、原因和重试关系；
3. 离线固定样本：工具正确率、检索命中、引用准确、拒答与异常语义；
4. LLM-as-judge：只作为相关性和事实一致性的辅助分数，不能覆盖安全或确定性失败；
5. 性能与成本：首事件时间、总耗时、Token、调用次数和费用。

## 7. 0.2 非目标

- AI 仓储写操作、自动审批和持久化业务草稿；
- MCP、A2A、MCP Apps、多 Agent、通用工作流引擎；
- AG-UI 或 CopilotKit 作为首版生产运行时；
- 第二套账号、权限、前端应用或业务 Service；
- Agent 直接 SQL、NL2SQL 或读取其他模块内部表；
- 外部独立观测平台和全量敏感内容回放；
- 为未来可能需求建设动态插件系统、远程 SDK 或微服务。

## 8. 已确认架构边界

- 0.2继续采用模块化单体，不切换微服务；
- AI、知识、观测、仓储和仓储适配通过同一应用内的Maven模块与公开Java API协作；
- 只有出现真实的独立部署、独立扩缩容、进程级故障隔离、独立团队发布或外部消费者需求时，才重新审议微服务；
- 当前不得预建服务发现、远程调用、分布式事务或微服务兼容层。

## 9. 2026-08-15 决策记录

- 部门改为树结构，采用最小完整父子关系，不做无调用方的复杂组织模型；
- 部门同时提供启停和受保护软删除，存在子部门、有效用户或仓库引用时拒绝删除；
- 仓库或位置归属部门，物品全局共享；
- 人工写包含入库、出库、调拨和盘点；
- Memory采用最后活动空闲TTL，默认4小时；History保留180天；
- 复用业务PostgreSQL时知识使用独立`ai_knowledge` schema；运行期知识不可用时只降级知识问答，仓储实时查询继续并明确提示；
- 聊天模型选择DeepSeek Flash，示例业务内容允许外发；
- Embedding模型选择阿里云百炼`qwen3.7-text-embedding`，向量维度固定为1024；
- AI观测run/step保留90天，feedback/evaluation保留180天；
- 调岗后的旧History仅本人可见，重新访问业务对象时按当前权限校验；
- 0.2继续采用模块化单体，不转微服务；
- 仓储人工操作提交后直接生效，不设置审批；
- 禁止负库存；库存移动记录暂不提供修改或删除能力。
- 库存数量精度确认为总19位、4位小数，超出精度直接拒绝。
- 四类库存操作支持有限多明细、整单备注和逐行备注；错误通过新盘点调整并关联原操作，旧流水保持不变。
